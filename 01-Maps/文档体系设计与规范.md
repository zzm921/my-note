# 文档体系设计与规范（v1）

> 本文是库的「宪法」：目录怎么分、笔记怎么写、怎么同步到线上站点。改规则先改这里。

## 一、现状诊断（2026-09-16 实测 180 篇）

| 问题 | 证据 | 影响 |
|---|---|---|
| **三层分类维度混用** | 同级目录既有「按技术栈」（node / golang / python / vue / docker），又有「按学科」（机器学习 / 计算机网络原理 / 数据库），还有「按用途」（面试题 / CICD / gitlab / 日志系统 / nas / windows） | 新笔记不知道放哪，找不到，越积越乱 |
| **大量无结构粘贴稿** | 135 篇技术笔记中，无 H1 的约 110 篇、无 H2 的约 70 篇（直接把文章粘进来） | 不能当卡片发布，检索与复习成本高 |
| **空文件 / 碎片** | ≥25 个 <1KB：`node学习node基础/.md`(0B，文件名空白)、`激活.md`(0B)、`elk.md`(0B)、`mongodb.md`(0B)、`格式化问题.md`(0B)、`实践.md`(0B)、`理论知识.md`(1B)、`语音识别.md`(118B)、`酷旗自动化构建及部署流程.md`(0B) … | 噪音，同步判断时全是误报 |
| **命名混乱** | 40 个含空格/中英混排：`Rag 评估.md`、`advance rag.md`、`naive  rag.md`（双空格）、`（应用层）HTTP vs HTTPS.md`、`解决类似 -usr-lib64-libstdc++.md`、`redis 5中基本数据类型详解.md` | 排序、链接、自动处理都别扭 |
| **同主题多份** | `node学习数据库/eslint.md`(18KB) vs `node学习vscode使用/eslint.md`(2.6KB)；`rag.md`/`naive  rag.md`/`advance rag.md` 与 `01~05-*RAG.md` 重复；三处 `README.md` | 不知道哪份是权威版本 |
| **目录深度/编号不一致** | `agent/01-基础概念/01-Agent是什么.md` vs `node/node学习node基础/…` vs `机器学习/1_机器学习笔记` vs 扁平 | 无法批量处理 |
| **附件两处** | 库根 `images/`（78 个）+ `.gitbook/assets/`（11 个） | 图片路径混乱 |
| **与站点关系无标记** | 全库仅 7 篇有 frontmatter，无「是否发布」字段 | 无法判断哪篇该上站 |

## 二、设计原则

1. **一层只用一个维度**：顶层按「用途/生命周期」分（收件箱 / 内容 / 日报 / 项目 / 生活 / 附件 / 归档 / 模板）；内容层才按「主题域」分；**技术域内部不再出现「面试题」「docker」这类用途或工具名当一级目录**。
2. **一篇笔记只属于一个目录**：跨域关系靠 frontmatter 的 `tags` / `domain` 表达，不靠复制文件。
3. **深度封顶三级**：`域 / 子域 / 笔记`。禁止 `node学习node基础/xxx` 这种「学习+技术」重复嵌套。
4. **命名规范**：中文或小写英文；**不含空格**（用 `-`）；序号只允许 `NN-` 一种前缀；文件名 = 笔记标题。
5. **收件箱机制**：新笔记先扔 `00-Inbox/`，每周整理一次归位；允许乱，但只有一个地方乱。
6. **归档而非删除**：过期提纲、碎片、旧版本一律进 `99-Archive/`（保留 git 历史与检索能力）。
7. **发布是显式动作**：只有 frontmatter 里写了 `site:` + `status: published` 的笔记才会上站（见《文档笔记→站点内容工作流》）。

## 四、文档格式规范

### 4.1 统一 frontmatter

```yaml
---
type: concept          # concept | tutorial | howto | issue | moc | daily | project
domain: AI/Agent       # 主题域（与目录一致，便于检索）
tags: [Agent, ReAct, 工具调用]
status: draft          # draft | living | published | archived
site: agent            # 可选：发布到站点哪个分区；不写=不上站
id: react              # 可选：站点卡片 id（与站点文件名一致）
difficulty: int        # 可选：beg | int | adv
created: 2026-07-01
updated: 2026-09-16
source: 课程/文章链接     # 可选：资料来源
---
```

### 4.2 标题与摘要

- **第一行必须是 H1**：`# 标题`（不带序号前缀，序号放文件名）
- **H1 后紧跟一行引用块**：`> 一句话说明本文覆盖什么：要点A、要点B、要点C`
  - 这行会自动成为站点的 `shortDesc`，也是自己复习时的抓手
- 正文只用 `##` / `###` 两级分节，**不用 H1 再分层**

### 4.3 五种笔记模板（放 `_Templates/`）

**① concept 概念卡**（术语、机制、原理）
```markdown
# 逻辑回归
> 二分类的概率模型：为什么线性回归不适合分类、Sigmoid、对数损失、决策边界。
## 定义
## 为什么需要它 / 解决什么问题
## 关键机制（公式 + 直觉解释）
## 与相邻概念的区别（对比表）
## 易错点
## 小结
```

**② tutorial 教程 / 课程笔记**（成体系的学习笔记）
```markdown
# 神经网络
> 本文覆盖：感知机 → 多层网络 → 反向传播 → 常见激活函数。
## 概述（本课在整门课中的位置）
## 概念与公式
## 手算示例
## 代码示例（可运行）
## 常见坑
## 小结与下一步
```

**③ howto 实操手册**（命令、配置、部署）
```markdown
# Nginx 反向代理 WebDAV
> 场景一句话 + 前置条件（版本、依赖）。
## 目标与前置条件
## 步骤（1/2/3，每步含命令与预期输出）
## 验证方法（怎么确认成功）
## 回滚 / 排错
```

**④ issue 踩坑记录**（故障与排查）
```markdown
# 服务器连接被重置（Connection reset）排查
> 现象一句话 + 最终结论一句话。
## 现象与影响面
## 排查过程（按时间线，含证据：日志/抓包）
## 根因
## 解决与验证
## 教训（下次如何更快定位）
```

**⑤ moc 地图 / 索引页**
```markdown
# AI · Agent 地图
> 本域包含哪些子主题、先看哪几篇、与站点的对应关系。
## 学习路径（按顺序列出笔记链接）
## 按子主题分组（[[笔记名]]）
## 待补 / 待重写清单
```

**⑥ daily 日报**（沿用现有 AI热点日报 格式，文件放 `90-Daily/2026/YYYY-MM-DD.md`）

### 4.4 命名与排序

| 场景 | 规则 | 示例 |
|---|---|---|
| 有顺序的课程/系列 | `NN-标题.md`（两位序号） | `01-机器学习导论.md` |
| 单篇主题笔记 | `标题.md` | `Redis持久化机制.md` |
| 目录 | 名词、无空格、无「学习」等冗余词 | `node/`、`mysql/`（不要 `node学习node基础/`） |
| 禁止 | 空格、双空格、`--`、`（）`、纯英文缩写大小写混排 | ~~`Rag 评估.md`~~ → `RAG评估.md` |

### 4.5 附件与双链

- 图片统一放 `99-Attachments/`（或子目录 `99-Attachments/2026/`），正文用 `![](99-Attachments/xxx.png)` 相对路径
- 双链 `[[笔记名]]` 只在库内使用；**发布到站点前必须转成普通文本或站内链接**（站点不渲染 `[[ ]]`）
- 需要跨库引用时用 `[[完整文件名]]`，不要用带路径的 markdown 链接（移动文件会失效）
