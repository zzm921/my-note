# Plan-and-Execute 范式

## 大纲

### 1. 概念
- 先由 LLM 生成**完整执行计划**，再逐步执行，每步结果作为下一步输入

### 2. 与 ReAct 的对比
| 维度 | Plan-and-Execute | ReAct |
|---|---|---|
| 规划时机 | 先一次性规划 | 边做边想 |
| 调用次数 | 少（1 次规划 + N 次执行） | 多（每步一次推理） |
| 灵活性 | 低（计划可能偏离实际） | 高 |
| 成本 | 较低 | 较高 |

### 3. 执行流程
```
1. 目标解析
2. 生成完整计划（步骤 + 依赖）
3. 逐步执行，每步结果回填
4. 汇总所有结果
5. 生成最终输出
```

```
计划:
  1. 搜索资料
  2. 提取关键数据
  3. 撰写报告
执行 → 结果1 → 结果2 → 结果3 → 汇总
```

### 4. 计划质量要求
- 步骤完整覆盖目标
- 依赖顺序正确
- 每步有明确输入输出

### 5. 动态修订
- 执行中发现计划不可行 → 局部修订计划
- 步骤失败 → 跳过或补充替代步骤
- 可以退化到 ReAct（计划内某步再细化）

### 6. 优点
- 减少 LLM 调用，成本可控
- 全局视野，不易迷失目标
- 适合流程明确的长任务

### 7. 缺点
- 计划可能脱离实际（执行不下去）
- 对突发信息响应慢

### 8. 适用场景
- 步骤明确、可预见的任务（数据处理、报告生成）
- 成本敏感的生产场景
