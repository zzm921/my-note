agent需要再记忆才能在多不任务中保持装填，夸任务积累知识。
记忆机制分层：
感知记忆：
单词请求生命周期内存放的未经加工的原始输入数据
工作记忆(短期记忆)：
agent当前回话县城内可以被大模型直接访问的运行时记忆
长期记忆
持久化存储，独立于单词会话，跨会话可用。
    情景记忆：保存历史交互时间轨迹，任务精力，对话摘要等半结构化信息
	实体记忆：从交互中抽取、沉淀出来的稳定结构化事实。



## 记忆存什么
通常值得存的有三类：用户偏好和习惯(语言风格、技术偏好、工作习惯)、任务执行中产生的关键结论和决策、以及外部知识。

不值得存的：中间的推理过程、工具返回的原始数据、闲聊内容等。


## 怎么存
- 需要语义检索的内容，比如文档知识、对话摘要这类非机构化文本，适合存进向量数据库，用embedding编码后通过相似度检索。
- 结构化的用户偏好和状态字段，比如语言偏好，项目配置这些可以精确查询的内容，适合用关系型数据库或者kv存储，查询速度快，不需要语义理解。
- 整段文档或知识库则适合存进向量数据库，配合rag流程做召回

混合 存储是主流做法：结构化的偏好字段用关系数据库精确查找，非结构化的知识和历史用向量数据库语义检索。


## 什么时候取出来用
两种策略：
主动检索：在任务开始前，用当前任务的描述去检索相关记忆，把结果注入 system prompt作为背景知识。
被动触发：agent在推理过程中，判断当前步骤是否需要某类特定的知识时，主动发起检索。具体做法是把查记忆分装成一个tool，让agent自己决定什么时候调用。
