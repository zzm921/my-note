# 容错、重试与可观测性

## 大纲

### 1. 必要性
LLM 有随机性、工具会失败、网络会抖动，生产级 Agent 必须容错 + 可观测。

### 2. 容错策略
| 场景 | 策略 |
|---|---|
| LLM 调用失败/超时 | 重试 + 退避（exponential backoff） |
| 工具执行失败 | 错误回传模型，让其换策略 |
| 输出格式错误 | 重试解析 / 重新生成 |
| 上下文超长 | 摘要压缩再调用 |
| 服务降级 | 降级到简化模式 / 兜底答案 |

### 3. 重试机制
- 限次重试：超过上限停止并给出兜底
- 重试变体：换模型、换参数、换 Prompt
- 退避策略：间隔递增，避免雪崩
- 熔断：连续失败暂停调用

### 4. 可观测性（三大支柱）
```
Logging  → 链路日志（输入输出、决策、耗时）
Metrics  → 成功率、延迟、Token 成本、工具调用分布
Tracing  → 单任务全链路追踪（感知→规划→行动→结果）
```

### 5. 观测内容
- 每轮 LLM 请求：Prompt、输出、token、耗时
- 每次工具调用：工具名、参数、结果、错误
- 规划轨迹：计划 vs 实际执行差异
- 状态变更：任务进度、检查点

### 6. 效果评估与优化
- 失败样本复盘：定位是检索/规划/工具哪一环
- 成本监控：token 与调用次数超限告警
- A/B 对比：Prompt/模型/策略版本对比

### 7. 工具链
- 框架自带回调（LangChain Callback）
- 观测平台：LangSmith / Langfuse / OpenTelemetry

### 8. 常见问题
- 只记录成功不记录失败
- 日志缺关键字段（无法还原现场）
- 重试无上限导致成本失控

### 9. 最佳实践
- 先埋观测再上线
- 每次变更（Prompt/工具/模型）可对比
- 建立失败案例库，持续驱动优化
