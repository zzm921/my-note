# 工具行动层（Action / Tools）

## 大纲

### 1. 职责
Agent 的"手脚"，负责把规划层的决策落地为真实动作：调用 API、操作数据库、执行代码、访问外部系统。

### 2. 工具类型
| 类型 | 示例 |
|---|---|
| 数据类 | 数据库查询、文件读写、API 调用 |
| 计算类 | 代码执行、公式计算 |
| 交互类 | 浏览器操作、发消息、发邮件 |
| 内部类 | 搜索记忆、调用其他 Agent |

### 3. 工具调用机制（Function Calling）
- 声明式工具定义：名称、描述、参数 Schema
- 模型根据任务选择工具并生成参数
- 系统执行工具，把结果回传给模型

```
tools = [{name, description, parameters}]
→ LLM 输出 tool_call {name, arguments}
→ 执行工具 → 结果注入消息
→ LLM 基于结果继续
```

### 4. 工具封装要求
- 输入输出结构化（JSON）
- 错误信息明确（失败原因可被模型理解）
- 幂等性：重复调用不产生副作用
- 超时与资源限制

### 5. 关键设计
- 工具注册中心：动态增删工具
- 参数校验：防止模型生成非法参数
- 结果截断：超长结果摘要化
- 权限控制：高危工具需要授权（见安全护栏）

### 6. 常见问题
- 工具幻觉：调用不存在的工具 → 严格按 schema 约束
- 参数编造：传了不存在的 ID → 校验 + 错误回传
- 工具调用死循环 → 限制单任务调用次数

### 7. 实现要点
- 工具描述要写清"什么时候用、参数含义"
- 提供示例参数（few-shot）提升准确率
- 工具执行与 LLM 推理解耦，可独立测试
