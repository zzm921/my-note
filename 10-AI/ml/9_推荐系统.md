# 推荐系统

> 本文以「预测用户对商品的评分（1~5 星）」为核心任务，展开推荐系统的两大主流路线——协同过滤与基于内容的过滤，并覆盖冷启动、大规模工程化等实践问题。

## 卡片：问题定义

**定义**
推荐系统的核心任务是：对每个用户 u 和每个商品 i，预测用户会给该商品的评分 ŷ(u,i)（如 1~5 星），再把预测分最高的若干商品推荐给用户。

**数据形式：评分矩阵**
- 行 = 用户，列 = 商品，格子 = 用户给该商品的评分；
- 矩阵**大多数格子为空**：用户只看过（并评分过）极少数商品，未知评分才是真正要预测的目标。

**实例：3 用户 × 4 电影评分矩阵（? 表示未知评分）**

| 用户\电影 | 电影1（动作） | 电影2（动作） | 电影3（文艺） | 电影4（文艺） |
|---|---|---|---|---|
| 用户 A | 5 | ? | 2 | 1 |
| 用户 B | 1 | 2 | 5 | 4 |
| 用户 C | 5 | 5 | 1 | 2 |

- 3 个用户、4 部电影，共 12 个格子，其中 11 个已知、1 个未知（用户 A 对电影2 的评分）；真实系统中矩阵往往是「百万用户 × 千万商品」，已知格子占比常不足 1%。

**两大主流方法**

| 方法 | 核心思路 | 数据需求 |
|---|---|---|
| 协同过滤（Collaborative Filtering） | 相似用户喜欢的东西也相似 | 只需历史评分矩阵 |
| 基于内容的过滤（Content-based Filtering） | 把用户偏好与商品属性做匹配 | 需要用户特征、商品特征 |

**为什么**
用户不可能看完所有商品，评分矩阵天然稀疏；推荐系统的目标，就是用已有的少数评分（或特征），把未知评分推断出来。

**直觉**
评分矩阵像一张「谁喜欢什么的记账本」：账本记录得越多，就越能猜出每个人接下来会喜欢什么。

**常见误区/注意点**
- 不要把「未知评分」当成「差评」——空格子只代表没看过，不代表不喜欢；
- 评分矩阵稀疏是常态，不是数据缺失事故，更不需要「补零」；
- 预测目标既可以是评分（回归），也可以是「是否购买/点击」（二分类），两者可互相转化。

## 卡片：协同过滤核心思想

**定义**
协同过滤只利用「用户-商品」评分矩阵本身，通过用户之间或商品之间的相似性来预测未知评分，不依赖任何用户画像或商品属性。

**两类思路**
1. **基于用户的协同**：找出口味与目标用户相近的一群用户，用这群人的评分来预测目标用户对未看过商品的评分。
2. **基于商品的协同**：找出「被同一批人喜欢」的相似商品（如动作片彼此相似），把目标用户已喜欢的商品的相似商品推荐给他。

**实例：用上面的评分矩阵说明「基于用户」的思路**
- 观察用户 A 与用户 C：A 给电影1 打 5 分，C 也给电影1 打 5 分；A 给文艺片打低分（2、1），C 也给文艺片打低分（1、2）→ A 与 C 口味高度相近（都爱动作片高分、不爱文艺片）。
- 现在要预测 A 对电影2（动作片）的评分：A 没看过，但 C 看过并打了 5 分。因为 A 与 C 口味相近，可以推断 A 也会给电影2 打高分（≈5 分）。
- 反观用户 B：B 给电影1 只打 1 分、给文艺片打高分（5、4），与 A 口味相反，所以 B 的评分对预测 A 没有参考价值。

**为什么**
人的口味是有「群体性」的：品味相似的人，对同一件商品的评价往往也接近。评分矩阵里其实隐藏着「品味相似的用户簇」和「被同类人喜欢的商品簇」，协同过滤就是把这个隐藏结构挖出来再用。

**直觉**
像交朋友：你发现某个朋友的口味和你出奇一致，于是他说好看的电影你基本也会喜欢——你借用了他的眼睛去看你没看过的电影。

**常见误区/注意点**
- 「相似」必须由数据定义（共同评过分的格子），不能拍脑袋；A 与 B 只在两部电影上有共同评分，样本太少，相似度不可靠；
- 协同过滤依赖评分量：评分越多、信号越强，一旦没有评分它就无能为力；
- 基于用户的协同在用户量巨大时计算很慢，工业界更常用基于商品的协同（商品数通常远少于用户数）。

## 卡片：协同过滤模型与训练

**定义**
给每个用户学一个偏好向量 w(u) 与偏置 b(u)，给每个商品学一个特征向量 x(i)，用两者的点积预测评分：ŷ(u,i) = w(u)·x(i) + b(u)。

**公式/伪代码**

```
对每个用户 u，维护参数：w(u)（偏好向量），b(u)（偏置）
对每个商品 i，维护参数：x(i)（商品特征向量）

预测评分：
    ŷ(u,i) = w(u)·x(i) + b(u)

目标函数（只在已知评分上求和）：
    J = Σ_{(u,i)∈已评分集合} ( ŷ(u,i) − y(u,i) )²
        + λ [ Σ_u (‖w(u)‖² + b(u)²) + Σ_i ‖x(i)‖² ]

训练（梯度下降）：
    循环：
        对每个用户 u：w(u) ← w(u) − α·∂J/∂w(u)，b(u) ← b(u) − α·∂J/∂b(u)
        对每个商品 i：x(i) ← x(i) − α·∂J/∂x(i)
```

**符号表**

| 符号 | 含义 |
|---|---|
| u | 用户下标 |
| i | 商品下标 |
| y(u,i) | 用户 u 对商品 i 的真实评分 |
| ŷ(u,i) | 模型预测的评分 |
| w(u) | 用户 u 的偏好向量，刻画「用户喜欢什么类型」 |
| x(i) | 商品 i 的特征向量，刻画「商品是什么类型」（如 [动作程度, 文艺程度]） |
| b(u) | 用户 u 的偏置，吸收「这个人打分整体偏高/偏低」 |
| λ | 正则化系数，控制参数不要过大 |
| α | 学习率，控制每步更新的步长 |
| ‖·‖² | 向量各分量平方和（L2 范数平方） |

**为什么**
- 商品特征 x(i) 是**自动学出来的**，不需要人工给每部电影标注「动作=0.9」：训练时梯度会同时更新所有参数，让 x(i) 自己收敛成「能解释已知评分分布」的向量；
- 「同时更新所有参数」的含义：w(u) 与 x(i) 互为对方的解释变量——只有知道用户偏好 w(u)，x(i) 才有意义；只有知道商品特征 x(i)，w(u) 才有意义。所以一轮梯度下降要把全部 w(u)、b(u)、x(i) 一起更新，反复迭代直到收敛；
- 只在已知评分上计算误差，未知评分不参与目标函数，这正是「用已有的少数评分学出全部参数」的关键。

**直觉**
把 w(u) 看作「用户的口味清单」，把 x(i) 看作「商品的配料表」，预测分就是「口味 × 配料」的匹配度——口味与配料越对得上，分越高。

**实例：手算一次预测**
假设已学出：
- 电影1 的特征 x(电影1) = [0.9, 0.1]（动作程度 0.9，文艺程度 0.1）；
- 用户 A 的偏好 w(用户A) = [2, 1]（偏爱动作片，也带一点文艺口味）；
- 用户 A 的偏置 b(用户A) = 0。

预测 A 对电影1 的评分：
```
ŷ = w·x + b = 2×0.9 + 1×0.1 + 0 = 1.8 + 0.1 = 1.9
```
即预测 A 给电影1 打 **1.9 分**。它偏低的原因是：虽然 A 的偏好向量分量不小，但电影1 的动作程度只有 0.9、文艺程度只有 0.1，点积结果天然有限。

**归一化（减用户均值）**
- 问题：有的用户「手松」全打 5 分，有的用户「手紧」全打 2 分。若直接训练，b(u) 会被学成「5」或「2」来迁就个人习惯，模型难以区分「商品本身好不好」和「打分的人手松手紧」。
- 做法：把每个已知评分先减去该用户所有评分的均值：y' = y − μ(u)。例：
  - 用户甲全打 5 分 → 均值 μ = 5 → 变换后所有评分变成 0；
  - 用户乙全打 2 分 → 均值 μ = 2 → 变换后所有评分也变成 0。
  - 两人相对口味一致时，模型看到的是同样的 0，不再被绝对分数误导；预测结束后再把用户均值加回去即可。
- 效果：模型学到的 w(u)·x(i) 反映「相对喜好」，评分偏差被消掉，商品特征不被个人打分手松手紧污染。

**常见误区/注意点**
- 点积结果可能不在 1~5 区间，需要截断或映射，不要指望模型天然输出合法星级；
- 正则化不能省：评分矩阵极稀疏时，参数容易过拟合少数几个已知评分；
- 归一化是对目标值的预处理，别忘了在预测后把用户均值加回去；
- 一个商品如果只有一两个评分，它的 x(i) 会被这少数用户的 w(u) 牵着走——样本量太小时学到的东西不可信。

## 卡片：冷启动问题

**定义**
冷启动指「没有足够行为数据」时无法做推荐的场景，分两类：新用户（无任何评分）与新商品（无任何用户评过）。

**为什么协同过滤会失效**
- 协同过滤的全部依据是「评分矩阵里的相似性」：新用户没有评分，就无法计算他与任何人的相似度，找不到「口味相近的用户群」；新商品没有评分，就无法计算它与任何商品的相似度，无法被推荐给任何人。
- 协同过滤本质是「用过去的评分猜未来的评分」，对零评分的对象，它没有任何过去可以借用，因此失效。

**内容过滤如何兜底**
- 基于内容的过滤不需要评分历史，只需要特征：
  - 新用户：用注册信息（年龄、性别、选择的偏好标签）构建画像，直接匹配商品特征给出推荐；
  - 新商品：只要有属性（类型、导演、年份）就能进入候选，被推荐给偏好匹配的用户。
- 其他兜底手段：热门榜（给所有人推全局最热商品）、用平均评分代替未知评分、人工规则。

**实例**
- 新用户小王刚注册，没有任何评分：协同过滤对他的行为矩阵是「全空行」，完全无法启动；但系统根据他注册时勾选「喜欢动作片」构建画像，就能直接匹配动作片并给出推荐。
- 新上映的文艺片还没有任何人打分：协同过滤无法把「没被任何人评过的商品」推出去；但系统知道它是文艺片，可以直接推荐给画像偏文艺的用户。

**直觉**
协同过滤像「听朋友的推荐」，但一个刚搬来的陌生人谁都不认识；内容过滤像「读商品说明书」，说明书不依赖你是谁，谁都能读。

**常见误区/注意点**
- 冷启动是常态而不是异常，工业界用「内容过滤 + 热门榜 + 探索」组合兜底；
- 新商品阶段要设计「探索」机制（如随机推荐给一小部分人收集评分），否则永远走不出冷启动；
- 不要因为冷启动存在就否定协同过滤：老用户/老商品上协同过滤精度更高，两者是互补关系。

## 卡片：基于内容的过滤

**定义**
基于内容的过滤利用用户特征 x(u) 与商品特征 x(i)，把「用户喜欢什么」和「商品是什么」配对来预测评分，不依赖其他用户的行为。

**公式/伪代码**

```
用户侧特征：x(u)（如年龄、性别、历史观看偏好、设备类型）
商品侧特征：x(i)（如类型向量、时长、出品年份）
用户口味向量：w(u)，由用户画像特征 x(u) 学出

预测评分：
    ŷ(u,i) = w(u)·x(i) + b(u)

训练方式与协同过滤相同：
    在已知评分上最小化 ( ŷ(u,i) − y(u,i) )² + 正则化
    区别在于：这里 w(u) 的输入来自用户画像 x(u)，而不是用户的历史评分本身
```

**符号表**

| 符号 | 含义 |
|---|---|
| x(u) | 用户 u 的画像特征向量（年龄、性别、偏好标签等） |
| x(i) | 商品 i 的属性特征向量（如 [动作程度, 文艺程度]） |
| w(u) | 由用户画像学出的「口味向量」，表示该用户对各类型的偏好权重 |
| b(u) | 用户偏置 |
| ŷ(u,i) | 预测评分 |

**为什么**
当某用户几乎没有评分时，我们无法从行为中推断他的口味，但可以从画像中推断：喜欢动作片的人，大概率给动作片高分。内容过滤把「画像 → 口味」这个映射学出来，从而对没见过的新用户也能工作。

**直觉**
像点外卖：平台知道你爱吃辣（画像），看到一家店写着「川菜、重辣」（商品特征），就知道你大概率会喜欢——全程不需要问别的顾客。

**实例：手算一次预测**
- 商品：电影6 的特征 x = [0.9, 0.1]（动作程度 0.9，文艺程度 0.1）；
- 用户：根据用户画像学出口味向量 w(u) = [3, 0.5]（很爱动作片，稍带文艺口味）；
- 偏置 b = 0。

预测分：
```
ŷ = w·x + b = 3×0.9 + 0.5×0.1 + 0 = 2.7 + 0.05 = 2.75
```
即该用户给电影6 预测打 **2.75 分**。其中动作分量贡献 2.7 分，是绝对主力；文艺分量只贡献 0.05 分——说明该用户的评分主要由商品的动作属性驱动。

**与协同过滤对比**

| 维度 | 协同过滤 | 基于内容 |
|---|---|---|
| 依据 | 其他用户的行为（评分矩阵） | 用户与商品自身的特征 |
| 新用户冷启动 | 无法推荐（无评分） | 可用画像推荐 |
| 新商品冷启动 | 无评分难推荐 | 有属性即可推荐 |
| 推荐多样性 | 可能推荐「意外惊喜」 | 偏「同类推荐」，容易同质化 |
| 特征成本 | 无需特征，自动学出 | 需要人工/系统构建高质量特征 |

**常见误区/注意点**
- 基于内容不是不要评分：w(u) 仍要靠「画像 + 历史评分」学出来，纯靠注册标签精度很低；
- 特征质量决定上限：特征坏，模型再好也白搭；
- 它容易陷入「信息茧房」：只推荐用户画像框定的类型，缺少惊喜；实际系统通常是协同过滤 + 内容过滤混合使用。

## 卡片：大规模推荐：召回 + 排序

**定义**
当商品数量上亿时，不可能对每个商品逐一精算评分。工业界把推荐拆成两步：先用廉价方法「召回」少量候选，再对候选「精算排序」，取 Top N 输出。

**公式/伪代码**

```
输入：用户 u，全量商品库 Items（规模可达百亿级）

第一步 召回（Retrieval）：
    用廉价打分方法（余弦相似度、倒排索引、热门榜）快速粗筛
    候选集 = {
        与用户历史喜欢的商品相似的 k 个商品
        ∪ 用户所在群体的热门商品
        ∪ 与用户画像匹配的商品
        ∪ 少量随机探索商品
    }
    # 目的：把 10^10 规模缩到 10^3 ~ 10^4 量级

第二步 排序（Ranking）：
    对候选集里的每个商品 i，用完整模型精算 ŷ(u,i)
    按 ŷ 从大到小排序
    输出 Top N（如 N=10）推荐给用户

返回：推荐列表
```

**符号表**

| 符号 | 含义 |
|---|---|
| Items | 全量商品库（如 100 亿个商品） |
| 候选集 | 召回阶段选出的商品子集（如 5000 个） |
| k | 召回阶段每个召回通道取的商品数 |
| ŷ(u,i) | 排序阶段精算的预测评分 |
| N | 最终推荐给用户的商品个数（Top N） |

**为什么**
- 精算评分（深度模型）单次开销大，若对 100 亿个商品全算，延迟不可接受；
- 但绝大多数商品与用户毫不相关，用廉价方法先丢掉它们几乎不损失质量；
- 召回追求「快而全」（宁可多给候选，别漏掉好商品），排序追求「准」（在候选内精挑细选）。

**实例：100 亿商品 → 5000 候选 → Top 10**
- 全量商品：100 亿 = 1×10^10 个；
- 召回阶段用余弦相似度 + 热门榜等廉价方法，把候选缩到 5000 个：规模缩小 10^10 ÷ 5000 = 2×10^6 = 200 万倍；
- 排序阶段只对 5000 个候选逐一精算预测分，按分排序，取前 10 名推荐给用户；
- 计算量对比：若精算一个商品耗时 1 毫秒，直接对全量精算需 10^10 × 10^-3 秒 = 10^7 秒 ≈ 115.7 天；两阶段法只需 5000 × 10^-3 = 5 秒，且推荐质量几乎不变。

**工程要点**
- 特征要做归一化：数值范围差异大（如「评分 1~5」vs「时长 0~300 分钟」）会拖慢训练；
- 推荐要兼顾业务目标：不只预测评分，还要控制新颖性（别总推老几样）、多样性（别一屏全是动作片）；
- 评估分两路：离线评估（在历史数据上模拟推荐）与在线评估（A/B 测试对比真实用户行为）。

**常见误区/注意点**
- 召回不是越严越好：候选太窄会漏掉好商品（召回率低），排序再准也没用；
- 两步的分工要清晰：召回管「快」，排序管「准」，不要用精算模型去做召回；
- Top N 取多少要看产品形态：信息流可以 N=几十，推送可能只需 N=3。

## 卡片：易错点与要点

| 要点 | 说明 |
|---|---|
| 两类方法互补 | 协同过滤依赖「评分量」，内容过滤依赖「特征质量」；单用任一个都会在某个场景失效 |
| 评分要归一化 | 先减用户均值再训练，避免「打分手松/手紧」的全局偏差污染商品特征 |
| 冷启动是常态 | 新用户/新商品要靠内容过滤、热门榜、探索机制兜底，不能指望协同过滤 |
| 大规模必须两阶段 | 召回 + 排序，避免对全部商品逐一精算；召回保「全」，排序保「准」 |
| 空格子 ≠ 差评 | 未知评分不参与目标函数，也不应被当作负样本处理 |
| 相似度样本要够 | 两个用户只共同评过 1~2 个商品时，算出的相似度没有统计意义 |
| 注意业务目标 | 只优化预测精度可能带来同质化推荐，要同时评估新颖性与多样性 |
| 混合是常态 | 实际系统通常是协同过滤、内容过滤、规则、探索的混合体 |
