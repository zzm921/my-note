# 模型评估与调优

## 训练/验证/测试集划分

**定义**：把一份数据按用途拆成互不重叠的三份子集——训练集负责学习参数，验证集负责选择模型与超参数，测试集负责最终验收，三者各司其职。

**标准划分与用途**：

| 数据集                   | 用途                     | 常见比例  |
| --------------------- | ---------------------- | ----- |
| 训练集（Training）         | 训练参数 w、b               | 约 60% |
| 验证集（Validation / Dev） | 选择模型、调超参数（如 λ、多项式阶数 d） | 约 20% |
| 测试集（Test）             | 最终评估真实泛化性能，只在验收时碰一次    | 约 20% |

**超参数 vs 参数**：
- **参数**（w、b）：训练过程中由优化算法自动学出来的，例如梯度下降每轮更新一次。
- **超参数**（λ、学习率 α、多项式阶数 d、网络层数）：训练前人为设定，不会在训练中自动更新，必须靠验证集上的对比来选择。

**为什么（设计动机）**：
1. 训练误差天然乐观。模型见过训练数据，可能「记住」而非「学会」，在训练集上自评就像闭卷考试前先看了答案。
2. 若直接用训练集选超参数，会选出「在训练集上得分最高」的模型——这正是过拟合的另一种形式，对没见过的数据未必好。
3. 验证集与训练集不重叠，能公平估计「新数据」上的表现，是选模型的客观裁判。
4. 测试集绝不能在调参过程中被偷看。它一旦参与过任何决策，评估结果就不再可信，等于考试题目提前泄给了考生。

**直觉**：训练集是平时做题，验证集是考前模拟，测试集是高考。模拟题可以反复刷来调整答题策略，但高考题只能考一次，考坏了无法重来。

**实例：用验证集选择多项式次数**：数据集共 500 个样本，按 60% / 20% / 20% 划分为训练 300、验证 100、测试 100。任务：用面积 x 预测房价 y，分别尝试 d=1、2、3 次多项式拟合，结果如下：

| 多项式次数 d | 训练误差 | 验证误差 |
|---|---|---|
| 1 | 18% | 19% |
| 2 | 12% | 12.5% |
| 3 | 3% | 16% |

分析过程：
- d=1：训练、验证误差都高且接近 → 欠拟合（高偏差），模型表达力不足。
- d=3：训练误差极低但验证误差明显回升 → 过拟合（高方差），模型把噪声也背了下来。
- d=2：训练、验证误差都低且差距很小 → 选择 d=2。

选定 d=2 后，可把训练集与验证集合并重新训练一轮（参数重新学习），最后用测试集做一次性评估，得到最终性能报告。

**常见误区**：
- 调参过程中反复使用测试集 → 数据泄漏，最终评估结果作废。
- 划分前不洗牌 → 数据按时间/来源聚成块，验证集分布与实际不符。
- 比例不是一成不变的，数据量极少时可用交叉验证代替固定留出法。

## 偏差与方差（Bias / Variance）

**定义**：偏差是模型预测的平均值与真实值之间的系统性差距（欠拟合），方差是模型对训练集变动过于敏感的波动程度（过拟合），二者共同决定泛化误差。

**公式**：

```
泛化误差 ≈ 偏差² + 方差 + 不可约误差
```

**符号表**：
- 偏差：多次训练模型预测的平均值偏离真实目标的程度；偏差高意味着模型太简单，连训练数据都拟合不好。
- 方差：换一份训练集重新训练后，预测结果抖动的程度；方差高意味着模型把训练集的细节和噪声都记下来了。
- 不可约误差：数据本身含有的噪声，任何模型都无法消除，构成误差下界。

**为什么（设计动机）**：
1. 模型太简单（如线性拟合非线性关系）→ 表达力不足，训练误差本身就高 → 高偏差。
2. 模型太复杂（如高次多项式）→ 训练集拟合得完美但泛化差，换一份数据结果剧烈波动 → 高方差。
3. 偏差与方差此消彼长：模型复杂度上升，偏差下降、方差上升，存在一个最优复杂度拐点。
4. 由于测试集不能碰，实际中借助「训练误差 vs 验证误差」的对比来间接诊断，不需要测试集参与。

**诊断表**：

| 训练误差   | 验证误差   | 诊断  | 含义                 |
| ------ | ------ | --- | ------------------ |
| 高（15%） | 高（16%） | 高偏差 | 欠拟合：模型太简单          |
| 低（1%）  | 高（16%） | 高方差 | 过拟合：模型太复杂          |
| 低      | 低      | 良好  | 泛化正常               |
| 高      | 低      | 异常  | 训练集与验证集分布不一致，或数据泄漏 |

**实例**：
- 例 A：训练误差 15%，验证误差 16%。两者都高且几乎重合 → 高偏差。模型对训练数据都没学好。对策：增加特征、换更大模型、减小正则化 λ、训练更久。
- 例 B：训练误差 1%，验证误差 16%。训练近乎满分、验证很差 → 高方差。对策：增加数据、减少特征、增大正则化 λ、简化模型。
- 记住：**加更多训练数据只对高方差有效，对高偏差基本无效**。

**直觉**：偏差像射箭「整体偏靶心一侧」，方差像「弹着点散乱」。高偏差是瞄得不准，高方差是手抖得厉害。

**常见误区**：
- 高偏差时疯狂加数据 → 浪费算力，曲线不降。
- 混淆 λ 的作用：λ 越大模型越简单；治高方差应增大 λ，治高偏差应减小 λ。
- 只看训练误差低就以为模型好 → 必须同时看验证误差。

## 学习曲线（Learning Curves）

**定义**：以训练样本数 m 为横轴、误差为纵轴，在同一张图上画出「训练误差随 m 的变化」和「验证误差随 m 的变化」，用来判断加数据到底有没有用。

**画法（伪代码）**：

```
对 m 取一组递增的值，例如 10、50、200：
    用前 m 个训练样本训练一次模型
    记录训练集误差 train_err(m) 与验证集误差 val_err(m)
在同一张图上画出两条曲线
```

**两种典型形态（文字示意图）**：

```
高方差（加数据有效）：
误差
  |  训练误差 ~~~~ 验证误差 ........
  |     低而平         高但持续下降，两线有明显差距
  +------------------------------> m

高偏差（加数据无效）：
误差
  |  训练误差 ~~~~ 验证误差 ........
  |     两线早早靠近并几乎重合，都不再下降
  +------------------------------> m
```

**数字实例**：两种形态下训练/验证误差随 m 的变化。

高方差形态（三次多项式拟合正弦数据）：

| m | 训练误差 | 验证误差 |
|---|---|---|
| 10 | 1% | 16% |
| 50 | 1.5% | 9% |
| 200 | 2% | 5% |

观察：训练误差始终很低，验证误差随数据增多从 16% 一路降到 5%，且与训练误差的差距在缩小 → 加数据继续有效。

高偏差形态（线性模型拟合非线性数据）：

| m | 训练误差 | 验证误差 |
|---|---|---|
| 10 | 15% | 16% |
| 50 | 15.2% | 15.8% |
| 200 | 15.5% | 15.8% |

观察：两条曲线早已贴在一起、都停在 15% 附近不再下降 → 加数据无效，应增强模型本身（加特征、换多项式、加深网络）。

**直觉**：学习曲线是模型能力的体检报告——验证误差仍在下降说明「没吃饱」，该加数据；两线已贴死说明「吃再多也没用」，该换食谱（改模型）。

**常见误区**：
- 只画训练曲线不画验证曲线 → 看不到差距，无法判断形态。
- 高偏差时看到曲线不再下降还继续堆数据 → 典型的浪费。
- m 的取值要覆盖足够范围（从很小到接近全量），否则看不出趋势。

## 误差分析（Error Analysis）

**定义**：在验证集上收集所有被分错的样本，人工逐个查看并按错误类型分组、统计占比，用数据决定先改进哪一类问题。

**流程（伪代码）**：

```
1. 在验证集上运行当前模型，收集所有预测错误的样本
2. 人工逐个查看错误样本，按错误类型打标签分组
   例如：雨天被识别为晴天、把狗识别为猫、模糊图片、背影当正面
3. 统计每一类的样本数量与占比
4. 按占比从大到小排序，优先解决占比最大的那一类
5. 先用小批量样本（如 100 个）快速估算占比，评估投入产出后再决定是否深入
```

**为什么（设计动机）**：改进资源有限，把力气花在占比最大的错误类型上收益最高。不先看错误长什么样就凭感觉堆数据或换模型，很可能抓错方向、事倍功半。

**实例**：验证集 1000 张图片，模型错分了其中 100 个样本，人工分组统计如下：

| 错误类型 | 数量 | 占比 |
|---|---|---|
| 雨天被识别为晴天 | 70 | 70% |
| 把狗识别为猫 | 8 | 8% |
| 其他 | 22 | 22% |

结论：70% 的错误来自雨天误判，应优先解决（例如补充雨天训练样本、加入光照/天气相关特征）；「狗→猫」只占 8%，投入产出比低，暂时搁置。

**直觉**：误差分析是「先看病历再开药」。看到病人不能直接说「多吃药（加数据）、换个医院（换模型）」，得先找出病因分布。

**常见误区**：
- 只统计错误数量，不人工查看样本 → 分不出错误类型，无从下手。
- 一次分析全部错误样本 → 太慢；先用 100 个小批量估算占比即可，比例稳定后再扩大。
- 拿测试集做误差分析 → 污染测试集，最终评估失去意义。

## 卡片：性能指标（混淆矩阵与精确率/召回率）

**定义**：混淆矩阵统计「实际类别 × 预测类别」的四种计数，是计算准确率、精确率、召回率、F1 等一切分类指标的基础。

**混淆矩阵（二分类）**：

```
                预测为正例     预测为负例
实际为正例         TP             FN
实际为负例         FP             TN
```

**符号表**：
- TP：实际为正例且预测为正例（命中）
- FP：实际为负例但预测为正例（误报）
- FN：实际为正例但预测为负例（漏报）
- TN：实际为负例且预测为负例（正确放行）

**关键指标公式**：

| 指标 | 公式 | 含义 |
|---|---|---|
| 准确率 Accuracy | (TP + TN) / (TP + FP + FN + TN) | 全部样本中猜对的比例 |
| 精确率 Precision | TP / (TP + FP) | 预测为正例的样本中，真正是正例的比例 |
| 召回率 Recall | TP / (TP + FN) | 所有真正例中，被正确找出来的比例 |
| F1 | 2PR / (P + R) | 精确率与召回率的调和平均 |

**实例：垃圾邮件检测（手算）**：500 封邮件，其中 400 封正常（负例）、100 封垃圾（正例）。模型预测结果：100 封垃圾中识别出 80 封、漏掉 20 封；400 封正常中误判 30 封为垃圾、正确放行 370 封。即 TP=80、FN=20、FP=30、TN=370。

逐步计算：
- 精确率 P = TP / (TP + FP) = 80 / (80 + 30) = 80/110 ≈ 72.7%
- 召回率 R = TP / (TP + FN) = 80 / (80 + 20) = 80/100 = 80%
- 准确率 = (TP + TN) / (TP + FP + FN + TN) = (80 + 370) / 500 = 450/500 = 90%
- F1 = 2PR / (P + R) = 2 × 0.727 × 0.8 / (0.727 + 0.8) ≈ 1.163 / 1.527 ≈ 76.2%

含义：90% 的邮件分对了；被标为垃圾的 110 封里约 73% 真是垃圾；100 封真垃圾里找回了 80 封。

**为什么准确率会误导**：类别严重不平衡时，全猜多数类也能拿很高的准确率。例如 10000 封邮件只有 100 封垃圾（占 1%），模型把全部邮件判为「正常」：准确率 = 9900/10000 = 99%，但召回率是 0——垃圾邮件一封没抓到。此时 99% 的准确率是彻头彻尾的假象，必须看精确率/召回率/F1。

**实例：癌症筛查中阈值对精确率/召回率的权衡**：1000 人参加筛查，其中 10 人患癌（正例）。模型对每人输出患癌概率 p，用阈值 θ 决定是否判阳性。
- θ=0.7（严格，只报高置信）：判阳性 8 人，其中 7 人真患癌 → TP=7、FP=1、FN=3。精确率 = 7/8 = 87.5%，召回率 = 7/10 = 70%。
- θ=0.3（宽松，宁可错杀）：判阳性 15 人，其中 9 人真患癌 → TP=9、FP=6、FN=1。精确率 = 9/15 = 60%，召回率 = 9/10 = 90%。

结论：阈值降低使召回率上升（漏诊变少）、精确率下降（误报变多）。癌症筛查中漏诊代价远大于误报，选低阈值更合适；若场景是「误删重要邮件代价高」，则应选高阈值。调阈值即可在两者间权衡，不必重新训练模型。

**直觉**：精确率问「报出来的准不准」，召回率问「该抓的抓全了没」。鱼与熊掌，阈值就是那个调节旋钮。

**常见误区**：
- 类别不平衡时只看准确率 → 被假象误导。
- F1 是调和平均而非算术平均，对较小的那个数惩罚更重，两者悬殊时 F1 会明显偏低。
- 混淆矩阵行列搞反：行是实际、列是预测；精确率看列（预测为正的那一列），召回率看行（实际为正的那一行）。

## 易错点与要点

| 要点 | 说明 |
|---|---|
| 测试集不能碰 | 调参只用训练集+验证集，测试集留到最终一次性评估；反复使用即泄漏，验收作废 |
| 先诊断再动手 | 高偏差（训练、验证都高）加数据无效，应增强模型；高方差（训练低、验证高）加数据/正则化才有效 |
| 别只看准确率 | 类别不平衡时准确率会误导，要用精确率/召回率/F1 配合判断 |
| 误差分析优先级 | 先解决占比最大的错误类型，用 100 个样本快速估算占比，性价比最高 |
| 学习曲线定方向 | 加数据前先看学习曲线：验证误差仍在下降 → 加数据；两线已贴在一起 → 改模型 |
| 阈值是可调旋钮 | 无需重训，仅调整分类阈值即可在精确率与召回率间权衡 |
| 训练误差低不等于好 | 训练、验证误差都低才算好；只低一个要警惕过拟合或数据泄漏 |
| 多项式阶数陷阱 | 阶数太低 → 高偏差（欠拟合）；阶数太高 → 高方差（过拟合）；用验证集找中间拐点 |
