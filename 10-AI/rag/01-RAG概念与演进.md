# RAG 概念与演进

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种把**外部知识库**接入大语言模型的架构：先生成时先从外部数据中检索相关内容，再把检索结果作为上下文注入提示词，最终让模型基于这些事实生成答案。

```
外部数据 ──索引──> 向量数据库 ──检索──> 相关片段 ──增强──> Prompt ──> LLM ──> 答案
                                                    ▲
用户问题 ────────────────────────────────────────────┘
```

## 为什么需要 RAG

| 大模型的局限 | RAG 的解法 |
|---|---|
| 知识截止时间，无法获取最新信息 | 实时检索最新数据 |
| 私有/领域知识不在训练数据中 | 把企业文档接入知识库 |
| 幻觉（编造事实） | 用检索结果约束生成，答案有依据 |
| 无法溯源 | 生成时携带引用来源 |

## RAG 的四大演进路线

1. **Naive RAG（朴素 RAG）**：最基础的"向量化 → 检索 → 拼上下文 → 生成"流程
2. **Advanced RAG（进阶 RAG）**：对入库、检索、生成环节做精细化优化
3. **Modular RAG（模块化 RAG）**：组件解耦、可插拔调度，引入路由器、多跳检索、自检等模块
4. **Graph RAG（图谱 RAG）**：基于知识图谱，解决复杂多跳与全局性问题

## 适用场景

- 智能问答（客服、文档问答）
- 企业知识库助手
- 垂直领域辅助写作
- 增强长尾、小众知识的生成质量
