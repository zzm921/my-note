# Agentic RAG

## 大纲

### 1. 概念
- 传统 RAG：单次"检索 → 生成"
- Agentic RAG：让 **Agent 自主控制检索过程**——决定是否检索、查什么、查几轮、结果不满意就换个方式再查

### 2. 与传统 RAG 的对比
| 维度 | 传统 RAG | Agentic RAG |
|---|---|---|
| 检索时机 | 固定一次 | 按需多次、可迭代 |
| 查询生成 | 用户原话 | 可改写、可拆解 |
| 路由 | 无 | 路由器分发（向量/图谱/API/直接答） |
| 结果校验 | 无 | 自检，不满意重试 |
| 多跳推理 | 弱 | 强（迭代检索） |

### 3. 核心流程
```
用户问题
  → 意图路由（直接答？检索？多跳？）
  → 查询规划（拆子问题 / 改写）
  → 检索执行（向量 / 混合 / 图谱）
  → 结果评估（信息是否充分？）
      ├─ 不足 → 再检索 / 换策略
      └─ 充分 → 生成答案（可带引用）
```

### 4. 关键设计
- 路由器（Router）：问题分类分发
- 检索循环（Retrieval Loop）：允许多轮召回
- 校验器（Validator）：判断上下文是否足够
- 引用溯源：答案可核查

### 5. 优势
- 检索更有目的性，回答复杂多步问题更强
- 减少无关检索，降低成本
- 支持"先检索→发现缺信息→再检索"的闭环

### 6. 挑战
- 循环次数控制（防死循环）
- 成本与延迟上升
- 路由与校验的可靠性依赖底层模型

### 7. 落地形式
- 把"检索"封装成 Tool，交给 Agent 自行调用
- 或使用编排框架（LangGraph / LlamaIndex 等）实现
