# 多 Agent 编排范式

## 大纲

### 1. 概念
- 把多个 Agent 按一定拓扑组织起来协作，各司其职，通过消息与共享状态协同完成任务

### 2. 编排拓扑
| 拓扑 | 结构 | 适用 |
|---|---|---|
| 流水线 | A → B → C 串行 | 流程固定 |
| 星型 | 主 Agent 调度多个子 Agent | 任务可拆 |
| 图状 | 任意连接、条件分支 | 复杂动态任务 |
| 环状 | 互相评审、迭代 | 质量敏感 |

### 3. 角色划分
- 规划者（Planner）：拆解任务、分配
- 执行者（Worker）：具体干活
- 评审者（Critic）：验收、反馈
- 协调者（Coordinator）：处理冲突、汇总

### 4. 关键机制
- 任务分配与去重
- 消息路由与超时
- 结果仲裁（不一致时怎么定）
- 终止条件与兜底

### 5. 状态与通信
- 共享状态：全局黑板（Blackboard）/ 共享内存
- 消息协议：结构化（from/to/type/content）
- 上下文传递：避免失真，必要时只传摘要

### 6. 框架支持
- LangGraph（图编排）
- AutoGen / CrewAI（角色协作）
- MetaGPT（软件公司模拟）

### 7. 收益
- 并行与专业分工
- 相互校验提升质量

### 8. 代价与风险
- 成本成倍（每个 Agent 都调 LLM）
- 协调复杂度、消息风暴
- 单点失败放大

### 9. 设计原则
- 从"单 Agent + 工具"开始，确认瓶颈再引入多 Agent
- 每个 Agent 职责单一、接口明确
- 全局状态单一事实源
- 全链路可观测
