# Agent 测评体系

## 大纲

### 1. 为什么要分层评估
Agent 链路长（规划→工具→生成），只看最终答案无法定位问题，需要**过程 + 结果**双维度评估。

### 2. L1 行为层（过程 · 确定性/轨迹）
| 指标 | 含义 |
|---|---|
| 工具选择准确率 | 是否选对工具 |
| 参数保真度 | 工具参数是否真实正确 |
| 轨迹一致性 | 执行路径与预期一致 |
| 协议合规性 | 遵循交互协议 |
| 护栏合规性 | 遵守权限与安全约束 |
| 任务成功率 | 端到端是否完成 |

### 3. L2 语义层（结果）
| 指标 | 含义 |
|---|---|
| 忠实度（Groundedness） | 答案基于事实，不编造 |
| 答案相关性 | 是否切题 |
| 正确性 | 对照金标准是否正确 |
| 上下文精确度 | 上下文中有用信息占比 |
| 拒答（Abstention） | 不确定时拒答而非编造 |

### 4. 评估方法
| 方法 | 适用 |
|---|---|
| 人工评测 | 上线前小样本 |
| 规则校验 | 协议/护栏/格式 |
| LLM-as-Judge | 大规模自动评估 |
| 基准测试集 | 回归与版本对比 |

### 5. 评估流程
```
构造测试集（任务+预期轨迹+金标准）
  → 运行 Agent 收集轨迹与输出
  → L1 轨迹比对 / L2 语义评分
  → 聚合指标 → 定位薄弱环节 → 迭代
```

### 6. 评估陷阱
- 只看任务成功率，忽略违规过程
- 评分标准不统一
- 测试集与真实分布偏差
- LLM 裁判有偏好偏差

### 7. 最佳实践
- L1 + L2 同时评估
- 测评流水线纳入 CI 做回归
- 指标口径团队统一
