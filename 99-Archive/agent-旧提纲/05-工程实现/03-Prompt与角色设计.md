# Prompt 与角色设计

## 大纲

### 1. 重要性
Prompt 决定 Agent 的行为边界、输出质量与可复用性，是"零代码调优"的主要杠杆。

### 2. 角色（System Prompt）设计
- 角色定义：你是谁（专业助手/分析员）
- 行为规范：怎么做事（先查证再回答）
- 边界约束：不做什么（不编造、不越权）
- 输出格式：用什么结构输出（Markdown/JSON）

### 3. Prompt 结构
```
System: 角色 + 规范 + 约束 + 输出格式
User: 任务描述 + 示例 + 背景
Tools: 工具定义（独立于 Prompt，模型原生支持）
```

### 4. 设计原则
- 明确具体：少用模糊词
- 示例驱动：few-shot 比说教有效
- 约束负面清单：明确"禁止 X"
- 输出可解析：结构化输出利于程序消费
- 动态注入：上下文/记忆/工具结果按需拼入

### 5. 常见 Prompt 类型
- 任务指令 Prompt（一次性）
- 角色 Prompt（长期稳定）
- 规划 Prompt（输出计划 JSON）
- 反思 Prompt（评估与修正）
- 评审 Prompt（多 Agent 验收）

### 6. 调优技巧
- 先出草稿，再针对失败样例迭代
- 加示例修正特定错误模式
- 用评测集量化 Prompt 版本效果
- Prompt 版本管理（避免改坏）

### 7. 常见问题
- Prompt 过长：成本高、模型注意力稀释
- 指令冲突：System 与 User 矛盾
- 注入攻击：用户输入包含恶意指令 → 隔离 + 校验

### 8. 安全性
- 用户输入与系统指令隔离
- 敏感指令走独立校验
- 输出过滤敏感信息
