# 权限与安全护栏

## 大纲

### 1. 必要性
Agent 拥有工具执行能力后，权限失控会带来真实风险（删数据、花钱、泄露信息），安全护栏是生产化前置条件。

### 2. 权限模型
| 维度 | 控制点 |
|---|---|
| 工具级 | 哪些工具可调用（白名单/黑名单） |
| 参数级 | 参数范围校验（金额上限、ID 合法性） |
| 操作级 | 高危操作人工确认 |
| 用户级 | 按用户/角色分配权限 |
| 资源级 | 调用次数、预算、超时 |

### 3. 权限校验流程
```
工具调用请求
  → 身份/角色识别
  → 工具权限校验
  → 参数校验
  → 高危操作二次确认（人工/审批）
  → 执行 / 拒绝（拒绝时回传原因）
```

### 4. 安全风险
- 提示注入：用户指令劫持 Agent
- 工具滥用：反复调用高成本/危险工具
- 数据泄露：工具结果含敏感信息外泄
- 越权操作：拿到未授权能力

### 5. 护栏设计
- 输入侧：用户输入清洗、指令隔离
- 决策侧：权限矩阵、审批流
- 输出侧：敏感信息过滤、脱敏
- 运行侧：限流、超时、熔断、审计日志

### 6. 审计与追溯
- 全链路日志：每次工具调用的请求/参数/结果/审批人
- 异常告警：异常调用模式触发告警
- 复盘能力：出问题能还原现场

### 7. 最佳实践
- 最小权限原则：只给完成任务所需权限
- 高危操作永远要"人"把关
- 权限可配置、可审计
- 定期权限复审

### 8. 常见问题
- 权限一次性给太多
- 只做校验不留审计
- 拒绝信息太模糊，模型无法理解调整
