## 二、迁移前准备（旧机）

1. **提交未提交改动**：`agent-lab`（未跟踪 `docs/content-workflow.md`、`frontend/miniconda.sh` ← 197MB，勿提交）、`reading-tracker`（`package.json` 有改动 + 未跟踪 `package-lock.json`）。
2. **记录基线**（迁移后比对）：my-note HEAD `59fd2de`｜agent-lab HEAD `c8a51bd`｜my-note 文件数 431（不含 .git）｜vaultsvc 属主文件 498。
3. **确认公网 IP 类型**：若是**弹性公网 IP（EIP）** → 直接解绑改绑新机，**DNS 零改动**；若是随实例的固定 IP → 需改 DNS，**提前把 TTL 调到 60s**。
4. **新机规格**：至少 2C4G + 40G ESSD（见 2C2G 可行性：稳态 ~1.0G，浏览器/构建会打爆，且旧机无 swap）；同地域（上海）以保持延迟；安全组放行 22/80/443/8080（8443 备用）。
5. **停机窗口**：用 rsync 增量，可实现 **≤10 分钟**切换。

## 三、迁移步骤

```bash
# ── Step 1 新机基础环境（同版本 Ubuntu 22.04）
apt update && apt install -y nginx git curl rsync python3 python3-pip openssl
# Node + PM2（reading-tracker 用）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install -y nodejs && npm i -g pm2
# Hermes（官方安装器，不要 rsync venv）
#   → 安装完成后用 `hermes gateway install` 重建 user 服务
# miniconda（site 后端依赖）→ 重装环境或用 venv 替代

# ── Step 2 账号与挂载（uid/gid 必须一致）
groupadd -g 998 vaultsvc && useradd -u 998 -g 998 -M -s /usr/sbin/nologin vaultsvc
mkdir -p /srv/vault /srv/davroot/note
echo '/root/workspace/my-note /srv/vault        none bind 0 0' >> /etc/fstab
echo '/root/workspace/my-note /srv/davroot/note none bind 0 0' >> /etc/fstab

# ── Step 3 搬数据（旧机执行；可重复跑，增量）
rsync -aH --info=progress2 /root/workspace/my-note/         NEW:/root/workspace/my-note/
rsync -aH               /root/workspace/agent-lab/          NEW:/root/workspace/agent-lab/
rsync -aH               /root/workspace/reading-tracker/    NEW:/root/workspace/reading-tracker/
rsync -aH               /root/.hermes/                      NEW:/root/.hermes/
rsync -aH               /root/.ssh/ /root/.pm2/             NEW:/root/
rsync -aH               /etc/nginx/                         NEW:/etc/nginx/
scp /etc/vault-webdav.env /root/vault-credentials.txt       NEW:/etc/  # 注意路径
mkdir -p NEW:/usr/local/bin && scp /usr/local/bin/vault_editor.py NEW:/usr/local/bin/
# 不搬：/usr/local/lib/hermes-agent（重装）、/root/miniconda3（可选/重装）、node_modules

# ── Step 4 重建服务
mount -a
cp vault-webdav.service vault-editor.service NEW:/etc/systemd/system/   # 从旧机 /etc/systemd/system/
NEW: systemctl daemon-reload && systemctl enable --now nginx vault-webdav vault-editor
NEW: loginctl enable-linger root && hermes gateway install    # ← user 服务必须这样装
NEW: pm2 start /root/workspace/reading-tracker/server/src/index.js --name index && pm2 save && pm2 startup
# ★ 给 site 后端补一个 systemd unit（现在是裸进程，必须补，否则重启即掉）
```

**site 后端 unit 参考**（`/etc/systemd/system/agent-lab.service`）：
```ini
[Unit]
Description=Agent Lab site backend (uvicorn)
After=network.target
[Service]
User=root
WorkingDirectory=/root/workspace/agent-lab/backend
ExecStart=/root/miniconda3/envs/py312/bin/uvicorn app.main:app --port 8000 --host 0.0.0.0
Restart=always
[Install]
WantedBy=multi-user.target
```
（建议去掉 `--reload`：生产不需要，且吃内存）

```bash
# ── Step 5 切换
# 旧机停写：systemctl --user stop hermes-gateway; systemctl stop vault-webdav vault-editor nginx; pm2 stop all
# 最后一次增量 rsync（秒级）→ 新机启动全部服务 → 改 DNS/EIP 解绑改绑
```

## 五、「迁移后所有项目都能跑吗？」——逐项判断

| 项目 | 判断 | 说明 |
|---|---|---|
| nginx + 证书 + 反代 | ✅ 能跑 | 配置文件与 pem/key 一起搬即可；到期日 2026-12-08，需另行续 |
| WebDAV（rclone） | ⚠️ 要修 | 必须重建 **vaultsvc uid/gid 998** + bind mount，否则 405/403 |
| vault 编辑器 | ✅ 能跑 | unit + 脚本搬过去即可 |
| Hermes（含微信、cron、库同步） | ⚠️ 要修 | `hermes gateway install` + `loginctl enable-linger root`；`.env`/`cron/jobs.json` 随 `~/.hermes` 搬 |
| site 后端（agent-lab） | ⚠️ 要修 | **现在是裸进程**，新机必须补 systemd unit；miniconda 环境要重建或整目录搬 |
| reading-tracker（PM2） | ⚠️ 要修 | 需 `pm2 save` + `pm2 startup`，否则不会自启 |
| GitHub 自动同步 | ✅ 能跑 | 靠 `~/.ssh/id_rsa` + cron，两者都搬即可 |
| 微信网关 iLink | ✅ 能跑 | 出站连接，与公网 IP 无关 |

**结论**：**内容类的东西（库、站点、配置）搬过去就能跑；但 3 个「没做成服务」的组件必须在迁移时补齐，否则一定坏**。加上属主与挂载，一共 6 个坑：

1. 属主 `vaultsvc` uid/gid 必须是 **998**
2. fstab 两条 bind mount（否则 `/srv/vault`、`/dav/note` 是空目录）
3. `hermes-gateway` 是 **user 服务** → `hermes gateway install` + `enable-linger`
4. site 后端**没有 unit** → 补 `agent-lab.service`
5. PM2 **未 save/startup** → 补
6. 公网 IP / DNS 切换（EIP 可移植则免改 DNS）

## 六、顺带体检发现（**不迁移也该修**）

1. **site 后端是裸进程**（PPID=1，无 unit）→ 现在这台机器重启一次，站点就挂了。
2. **PM2 未 `pm2 save` + `pm2 startup`** → 同上，重启后 reading-tracker 不会自启。
3. **证书是手工文件 + certbot 空转**（`certbot certificates` = No certificates found，timer 在跑但无可续证书）→ 2026-12-08 到期会直接全站 HTTPS 失效；建议要么改用阿里云证书（带自动部署），要么重新配 certbot 自动续期。

## 七、回滚方案

- 旧机在切换后**保留 3–7 天不动**（服务停掉、数据不删）。
- DNS 回切（TTL 60s）或 EIP 解绑改绑回旧机 → 5 分钟内恢复。
- 数据以新机为准时，先在新机 `git status` 确认库完整，再决定是否清理旧机。
