# 微信绘本群「好价监控」方案调研

> 只做调研与方案，未实施。调研日志：`~/.hermes/logs/picturebook-deal/research_2026-10-11.log`

## 一、需求拆解

- **输入**：若干**个人微信群**消息（绘本好价分享群），非企业微信。
- **目标**：识别「我想要的绘本 + 好价」→ 通知/转发给我。
- **隐含需求**：去重（同一好价被多群转发）、可维护「想要的绘本 + 心理价」、低打扰（只在命中时提醒）。
- **硬约束**：微信个人号**没有官方 API**；微信侧主动推送受「会话窗口」限制（iLink 只在你最近发过言的窗口内允许主动推消息，即日报偶尔被拒发的原因）。

## 二、三条技术路线

| 路线 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **A. Android 通知监听**（推荐） | 手机侧监听「微信」通知，命中规则才转发 | 免 root、不碰账号协议 → **零封号风险**；小米 14 现成可用；成本 0 | 只拿得到通知里可见的文本（长消息可能被折叠/截断）；手机需常驻在线 |
| B. Windows 客户端 hook | wxauto / WeChatFerry 挂在 PC 微信上 | 能读**完整**群消息、可自动回复/转发 | 需一台常开 Windows + 微信登录；**违反微信协议、有封号风险**；客户端升级即失效 |
| C. 协议 / 云控（wechaty puppet、付费 pad） | 模拟客户端协议 | 不依赖手机/PC | 个人号 puppet 基本停维护、封号风险最高、需付费 |

**结论：优先 A**。只有当你发现「通知里看不到价格（比如卖家发图）」时，才考虑 B（且用一台不常用的 Windows）。

## 三、现成开源工具（已查证维护状态）

### 采集端 · Android（首选）
- **pppscn/SmsForwarder（短信转发器）** — 监控 Android **短信 / 来电 / APP 通知**，按**规则**转发到：钉钉群机器人、企业微信群机器人、飞书、**Webhook**、Telegram、邮箱、Bark、Server酱、PushPlus 等。开源、活跃、免 root。
  → 直接满足「微信群通知 → 命中关键词 → POST 到我的服务器」，**本方案首选采集件**。
- 备选：`NotificationListener → REST API` 类小项目（自研成本约 1–2 天）；Auto.js / Hamibot（无障碍读屏，能拿更多文本，但要写脚本）；MacroDroid / Tasker + AutoNotification（闭源但配置最快）。

### 采集端 · Windows（备选，路线 B）
- **cluic/wxauto** ★7.4k — Windows 微信客户端自动化（非网页版），可收发消息、读群消息；仍在维护。
- **fanyuantaier/wechatauto-replica** ★407 — wxauto 的复刻，**支持微信 4.x**，2026-10 仍在更新。
- **lich0821/WeChatFerry** ★6.8k — 微信 hook 机器人（可接大模型），有 Rust 客户端与 Docker 方案。
- **wechaty** ★23k — RPA SDK 生态（注意：个人号 puppet 多数已停维护）。

### 服务端 · 过滤 / 比价 / 提醒（可复用骨架）
- **sansan0/TrendRadar** ★63k — 多平台热点聚合 + RSS + 智能提醒；其「关键词 + 去重 + 定时推送」骨架与本需求同构。
- **archie96211/smzdm**（什么值得买好价监控桌面机器人）— 极小的参考实现：关键词筛好价 → 推钉钉/微信。可直接抄它的关键词与推送结构。
- **changedetection.io / Huginn / n8n** — 通用变更监控与编排（若还想直接抓商品页价格，而不只靠群消息）。
- **通知通道**：Server酱 / PushPlus / 企业微信群机器人 / 邮件（Bark 仅 iOS，你是 Android → 不用）。

## 四、推荐方案（分层架构）

```
[小米 14 · Android]                      [阿里云上海 ECS]                        [通知]
微信群通知
   │
   ├─ SmsForwarder：规则 = 群名 + 关键词（绘本/满减/券后/好价…）
   │        └── Webhook POST ─────────▶  ① 落库：原始消息（JSONL，按天分文件）
                                        ② 清洗：价格抽取（¥/元/到手价/券后）
                                        ③ 匹配：绘本书单 watchlist.yaml（书名/别名/系列 + 心理价）
                                        ④ 去重：hash(书名+价格)，24h 窗口内只提醒一次
                                        ⑤ 排序：低于心理价 / 折扣力度 → 优先级
                                              │
                                              ├─▶ 微信（会话内推送；窗口外由 outbox 在你开口时补发）
                                              ├─▶ 邮件（可靠兜底，himalaya）
                                              └─▶ 企业微信群机器人（可选，秒级、不受会话窗口限制）
```

**关键设计点**

1. **书单与价位**放在 `watchlist.yaml`（书名 / 别名 / 系列 / 心理价 / 折扣条件）——比关键词表好维护，因为绘本同音字、系列名、别名很多。
2. **两级过滤**：手机上（SmsForwarder 规则）做**粗筛**，省流量与成本；服务器做**精判**（书名归一化：去书名号/表情/别名 + 价格抽取 + 心理价判定）。
3. **价格识别**：正则抓 `¥/元/到手价/券后/折`；遇到「满减/凑单」优先取「到手价」，取不到就把原文片段留给你人工判断。
4. **去重**：`hash(书名 + 价格)` + 24h 窗口；同一好价被多个群转发时只提醒一次。
5. **通知分层**：主通道微信（受会话窗口限制 → 配合 outbox 补发）；兜底邮件；要「秒级且不受限」就加企业微信群机器人（自建群、自定义机器人 webhook、零成本）。
6. **全程留痕**：原始消息 + 判定结果落 `~/.hermes/logs/picturebook-deal/`，可选每日摘要。

## 五、风险与限制（实施前必须知道）

1. **无官方 API**：A 路线只读通知、不碰账号协议，风险最低；B 路线有**封号风险**且随客户端升级失效。
2. **通知文本可能被截断/折叠**：长消息与**图片消息**（很多绘本群发图报价）拿不到内容 → 图片类好价需人工或走 B 路线。
3. **微信主动推送受会话窗口限制**：秒级通知建议走企业微信机器人/邮件，否则只能"你开口时补发"。
4. **手机必须在线且通知权限常开**：小米的省电策略要加白名单，否则会漏消息。
5. **服务器在国内**：通知通道选国内可达的（企业微信 / 邮件 / Server酱），不要用 Telegram/Google 依赖。
