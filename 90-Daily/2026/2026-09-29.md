## 🧩 Agent 开发
- **Cloudflare 提出「智能体开发生命周期（ADL）」并给出一整套原语**（InfoQ 9-28，原文 blog.cloudflare.com/agent-development-lifecycle/，已核）。① 编排层用 **Workflows**：不是静态流水线，可动态生成容器、跑无头浏览器、调度子 Agent；② 开源 **@cloudflare/ci**，直接跑在 Workflows 上，负责步骤串联、依赖缓存与凭证管理，让 Agent 自主做故障处理与分诊；③ 为**每个 Agent 创建预览部署**，并行对照生产测试，绕开预发瓶颈，变更要求原子性；④ 兼容 **OpenTelemetry** 的可观测面板，能看到单次模型调用、工具执行与 token 消耗，支持回放会话、查看子 Agent 交接、调试畸形入参（与 Think、Flue、AI SDK 原生集成）。→ 今天就能抄三件事：给每个 Agent 起独立预览环境、把「Agent 的 CI」写成事件驱动工作流而非固定流水线、工具与模型调用统一打 OTel span。
- **Strands 开源「组装好的 Agent harness」，同模型下 token 省 28%**（开源中国 9-28）。→ 省的应该主要在上下文组织与工具结果处理这一段，值得拿同模型跟自己的 harness 做 A/B；⚠️ 28% 为项目自测口径。本次没抓到正文（OSCHINA 是前端渲染）。
- **openai-python v3.20.0**（GitHub Release 9-28）：feature 明确写着 **add Agents credential and session options**。→ 用 OpenAI SDK 起 Agent 的，`pip install -U openai` 即可拿到官方对 Agent 凭证与会话的原生选项，少写一层自己封的会话管理；升级后逐条核对 credential 的存储与过期语义。
- **OpenAPPA：开源的确定性护栏**（Show HN 9-28，22 分/11 评，openappa.com），自述「deterministic guardrails that don't break agents」。→ 提示词层软约束不可靠时的另一条路线：把越权/危险动作的判定做成确定性代码路径，而不是再补一句「请不要」。可先读它的裁决模型，再决定接入还是自研。
- **DoorDash 用多 Agent LLM 系统清掉 6 万个 Feature Flag**（InfoQ 9-26）。→ 「大批量、低风险、可校验」任务的真实编排案例：角色怎么拆、爆炸半径怎么控、结果怎么校验，可对照自家批处理型 Agent 的设计。

## 💰 成本与基础设施
- **arXiv（cs.AI，9-26 提交，已核原文）DeepEdu-v1 / SCALE 框架**：① 长上下文推理引擎把 token 选择粒度从「子块」提升到「簇」，长上下文检索的调用次数比选择性注意力基线少 **7.7 倍**，prefill（TTFT）降约 **35%**；② 一个自我改进的 agentic 层通过从历史交互中持续沉淀「可核验的 playbook」来替代微调；部署配置下 TTFT 比标准 vLLM 快近 **2 倍**，复杂任务 agent 准确率 70.0% → **79.5%**。→ 两个可迁移的点：RAG/记忆检索别只按块打分，试试按簇做 token 选择；让 Agent 自己攒 playbook 表，比反复微调便宜得多。论文是越南教育场景的生产系统报告，方法与领域无关。
