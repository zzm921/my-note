## 🤖 大模型

**智谱 GLM-5.4：首个 Loop Transformer 旗舰，750B 级、1M 上下文，中间 28 层算两遍**
把中间 28 层算完第一遍后送回起点、用同一套权重再算一遍（训练算力仅 +10%），两轮各加一个门控调节写回幅度；部署侧把 KV Cache 按远近拆开（远端两轮共用、近期各存一份），并复用第一轮的稀疏注意力索引，所以上下文拉到 1M 也只多存滑动窗口那一小段。30B 同参对照：AIME25 19.17→30.42、GPQA Diamond 47.58→56.26、MMLU-Pro 71.65→75.05，平均输出 token 反而少 11.7%–14.9%；非高峰 200 tok/s、高峰 70–80 tok/s。权重将在安全加固后开源。
对 Agent 的含义：「内部多算一遍、外部少写一堆 reasoning」正是 agent loop 最想要的形状——同任务更少输出 token、更低延迟；1M 上下文下 KV 只按滑动窗口增量，长会话/大仓库的显存估算要按这个新结构重算。
https://www.qbitai.com/2026/11/512423.html

**文心 5.5 Flash Preview 开源（Apache 2.0）：2800 亿总参、每 token 激活 140 亿、100 万上下文**

https://www.qbitai.com/2026/11/512354.html ｜ https://huggingface.co/baidu/ERNIE-5.5-Flash-Preview

## 🧩 Agent 开发

**谷歌实测「智能体分心」：陈旧 TODO 让编码 agent 多跑 70% 步骤、多烧 77% token**
对数亿次 agent 操作做分布式追踪：13% 的会话碰到内联 TODO/FIXME，其中 6% 真的去处理了；这些没被提示的绕道里，41% 针对已关闭工单、57% 属于超出请求的范围蔓延。代价是每会话步骤 +70%、token +77%、等待 +105%。谷歌的解法是清理 agent：查最长数年的 Git 历史确认 TODO 及其意图都已过时，才提 PR 删除，6 个月清掉数千条，人工审核通过率 >95%。
对 Agent 的含义：注释、规格、旧 issue 都是上下文的一部分——进 context 前先按「工单是否已关闭 / 规格是否已过时」过滤；给编码 agent 加一道提交前分析器，比事后加一轮 self-check 便宜得多。
https://www.infoq.cn/article/sFmubmDWkulIOTBLX0Dr

## 📊 评测与基准

**Know When to Abstain（arXiv 2611.31175）：用共形预测给 Text-to-SQL 定「该不该答」的置信度**
Avinash Kumar Singh 等，把 conformal prediction 用在 Text-to-SQL 的置信估计上，目标是让模型没把握时弃答，而不是硬编一个查询。
对 Agent 的含义：工具型 agent 最贵的错误是「编参数硬调」；这套思路可搬到任意工具调用——给每次调用一个可校准的弃答阈值，比统一调 temperature 靠谱得多。
https://arxiv.org/abs/2611.31175

官方定位为开源运行时，用于在补丁落地前屏蔽未修复漏洞的利用路径（具体机制未在素材中展开）。

**arXiv：模型会被注入的「不确定性 token」带偏，却在真实场景里不会就地自我监控**
Daniel Theron，题名即结论：注入的 uncertainty token 能影响模型行为，但模型不会 in situ 自我监控（仅题名，摘要未入库）。
对 Agent 的含义：别指望模型自己发现「我不确定」——不确定性必须外部化：结构化输出里强制 confidence 字段，由 harness 判定是否追问或降级，而不是靠 prompt 提醒它「注意不确定」。
https://arxiv.org/abs/2611.31215
