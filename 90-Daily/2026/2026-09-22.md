## 🧩 Agent 开发

- **Google 开源 AX：把 Agent 当集群工作负载的声明式编排器**（开源中国 9-21）。声明式描述 Agent 任务、交给集群调度，解决的是"单机脚本式 Agent 撑不住并发"的问题。若你要跑批量 Agent（评测集、爬取、CI 里的编码 Agent），这是少见的编排层方案；先看它能否复用你已有的工具/MCP 定义。
  https://www.oschina.net/news/502639/google-ax
- **browser-use/jev-ultrafast ★15107**（9-16 建仓，"最快最便宜的 web agent"），同期 HN 热帖 Kev/Jev 是"**判断模型**"——不生成文本、只输出判断，用来给 Agent 提速。接入点：把"是否点击/是否继续"这类决策交给小判断模型，省掉大模型的一次完整生成。国内也有专文《Jev 凭什么刷屏：一个不生成文本的"判断模型"》。
  https://github.com/browser-use/jev-ultrafast ｜ https://www.oschina.net/news/502633
- **Foremerge（Show HN）**：检测多个**并行编码 Agent** 之间的意图冲突——多 Agent 改同一仓库时互相覆盖的典型事故。若你并行开 Claude Code / Codex 多个会话，值得接入。
  https://github.com/naw103/foremerge
- **框架版本一轮收**：`llama_index v0.14.25`（含 `llama-index-agent-agentmesh 0.3.0`，修了一批安全告警）、`langgraph 1.2.12`、`langchain-core 1.6.4`（后两者为构建/nightly 标签级发布）。升级：`pip install -U llama-index langgraph langchain-core`。
- **纯 LLM 做 NL2SQL 总不准？金融场景必须做本体工程**（InfoQ 9-21）：只把 schema 塞进 prompt 不够，要把业务本体（口径、指标定义、join 约束）显式建模后作为工具上下文喂给 Agent。写 Data Agent 类工具可直接照搬。
  https://www.infoq.cn/article/TcTrU2Ap9VsxxHVestfw

## 🔥 值得深看

1. **Google AX**（开源中国）——目前少见的"把 Agent 当集群工作负载"的声明式编排器。你要做批量/并发 Agent 任务时，它可能比"自己写队列"更省事。
