**6. Claude Code v2.1.319：auto 模式在关掉遥测/特性开关后不再静默降级**
改动点：当遥测或 feature flag 关闭（包括跑在 LLM 网关后面）时，服务端无法校验的调用一律「先问或拒绝」，不再回落到内置分类器；要保留老行为设 `CLAUDE_CODE_AUTO_MODE_SERVER=0`。**走自建网关、代理或内网镜像的团队，升级前先确认这条**，否则会出现成片的确认弹窗或拒绝。
→ https://github.com/anthropics/claude-code/releases/tag/v2.1.319

**9. InfoQ《智能体 Harness 的演进：从链、图到代码化》——LinkedIn 的实战复盘**

→ https://www.infoq.cn/article/B7tsA5tjD08k2gd0OtXd

## 📊 评测与基准

**10. arXiv《Benchmarks as Software》：基准该当软件维护，不是一次性榜单**

## ⚠️ 安全与踩坑

**13. Claude Code 把用户邮箱写进 User-Agent 发给第三方站点（HN 1494 分/468 评，issue 仍 open）**
v2.1.318 及更早版本做网页抓取时在 UA 里带上了账号邮箱，报告者称因此收到大量诈骗邮件（issue 107757，93 条评论）。两件事现在就能做：一是升级并检查自己 harness 里有没有把身份信息拼进 UA/Referer；二是自建抓取 agent 统一用服务标识 UA，绝不带个人或组织可识别信息——很多站点会把它记进日志并转卖。
→ https://github.com/anthropics/claude-code/issues/107757

**14. anthropic-sdk-python v2.6.0：新增 ramp limit 与 External Key 校验失败错误码**
配合 v3.47.0 的 openai-python（Responses 增加 model 选项）。实操点：限流类错误（ramp limit）该退避重试，密钥/配置类错误（External Key 校验失败）重试只会放大故障——把这两类错误码分开处理后，agent 的失败率统计才不会被无效重试污染。
→ https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.6.0 ｜ https://github.com/openai/openai-python/releases/tag/v3.47.0
