## 🧩 Agent 开发

**4. Claude Code 团队怎么让 Agent「拿证据证明自己对」（HN 169 分/151 评）**
claude.dev 博客（Addy Osmani，11-16）：该团队约 90% 代码由 Claude 写并评审；核心是 verification loop——没有它一次只能并跑 1-2 个 agent，有它才能跑几十到几百个。内部测试里「独立 grader 按 rubric 打分」比普通 prompting 循环最高提升 10 个点，难题收益最大。
对 Agent：今天就能加一个独立评分环节（换模型/换 prompt），把反复失败的用例固化成 hook 或规则文件；文中主推三类测试：E2E、property、differential。
https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/

**7. Jetriever：记忆检索不该按「像不像」，而该按「有没有用」（arXiv 2611.21478）**
把相似度检索换成对全量记忆做「决策分数」排序。InMind 125 个间接查询任务上，目标记忆被排到第一位 84.8%，同条件的 BM25 = 1.6%、MiniLM = 0.0%。
对 Agent：按 embedding top-k 取记忆，遇到「上次那个配置」这类间接提问几乎必失效；可先加一路「用当前问题给每条记忆打可用分」的轻量重排，与向量检索做 A/B。
https://arxiv.org/abs/2611.21478

## ⚠️ 安全与踩坑

**13. 靠「文本相似度」拦 Agent 间注入，会同时漏报和误报（arXiv 2611.21520）**
Agent 互传信息时，注入指令改写措辞后仍会影响下游；而正常引用/模板复用会有高文本重合。作者用 DonkeyRail（BLEU+ROUGE-L+METEOR 特征分类器）证明这两类被混为一谈。
对 Agent：多智能体链路里别拿相似度阈值当安全闸门——要么在结构化字段上加来源标签与权限（谁能改谁的指令），要么从能力侧限制（工具授权、出口过滤）；文本层拦不住。
https://arxiv.org/abs/2611.21520
