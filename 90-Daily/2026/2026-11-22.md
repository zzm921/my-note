## 🤖 大模型

**Thinking Machines 的 Inkling 2 Mini 进了 Ollama：26B 总参 / 5.4B 激活**
ollama v0.40.17 直接内置该模型；HF 镜像趋势 ↓7944 / ♥1116，unsloth 已出 GGUF（♥364）。官方说明它的「循环层」让每 token 的计算量高于参数规模所暗示的水平 —— 换句话说，它拿时间换质量，适合当本地 agent 的执行层：工具调用、意图分类、子任务执行这类高频短请求，不必走公网 API。
今天就能做：`ollama run inkling-2-mini`，或拉 unsloth 的 GGUF 到 llama.cpp 起 OpenAI 兼容端点，把它挂成 agent 的「廉价执行档」。
https://github.com/ollama/ollama/releases/tag/v0.40.17 ｜ https://hf-mirror.com/thinkingmachines/Inkling-2-Mini

**arXiv AutoMaster：让同一个模型当自己的老师，做「自主后训练」**
方法点是不引入更强的外部教师，而由模型本身为失败样本生成更高质量的训练信号，形成自举闭环。对 agent 的可迁移点不在训练环节，而在它那套循环：评测 → 失败归因 → 重写轨迹 → 再验证 —— 正好对应 agent 的经验回写（把失败轨迹改写成可复用做法）。
https://arxiv.org/abs/2611.26492

## 🧩 Agent 开发

**browser-use 1.0.8rc1：judge 变成 run 里多跑一轮，评估不再重复计费**
改动点很具体：评审（judge）现在作为同一次 run 的「再加一轮」提交给 provider，provider 直接从缓存读整条 run，而不是把 trace 再计费跑一遍；返回字段不变（含 gotchas）。对跑批量评测的 agent 项目意味着账单结构变了，可以更大胆地把 judge 放进主循环做逐步护栏。
今天就能做：`pip install 'browser-use==1.0.8rc1'`（RC 版，生产先灰度一路流量）。
https://github.com/browser-use/browser-use/releases/tag/1.0.8rc1

**Show HN：OpenComputer ★994 —— 开源的 Devin 替代（TypeScript / Apache-2.0）**
定位是「更快」的自主编码 agent，可整体 self-host；11-21 仍在推代码（pushed 16:29），并非弃坑项目。价值在于它是一套能跑的端到端骨架（会话、工具、容器执行、产物回收），自建 coding agent 平台可以对着改，而不是从零拼。
注意：星数刚到四位数、接口还在变，别直接当生产依赖。
https://github.com/diggerhq/opencomputer

**Jane Street 开源内部 agent skills ★10.5k：首个技能 socratic-tutor（MIT）**
用标准 `SKILL.md` 目录结构，拷进 agent 的 skills 目录就能用（普通 chatbot 也可整段塞进 system prompt）。内容是严格家教流程：先诊断 → 建 0-5 级技能图谱 → 一次只问一题 → 间隔复习 → 终局评估；仓库说明它是从公司日常在用的内部仓导出的，明确不收改文本的 PR。
值得抄的不是题目，而是「把长流程写成可执行状态机」的写法 —— 同一骨架能套成 code review 教练、onboarding 向导、故障复盘引导。
https://github.com/janestreet/agent_skills

**arXiv MemFolder：结构引导的「记忆折叠」，压 agent 记忆的检索开销**
不是按时间窗口截断历史，而是按结构把长程对话/工具记录折叠成层级摘要，检索时只按需展开对应层。可直接借鉴的结论：记忆系统的关键不是「存多少」，而是「按什么结构折叠、按什么键展开」—— 比再调一次 top-k 更省 token。
https://arxiv.org/abs/2611.26358

## 📊 评测与基准

**arXiv LLM GerryMandering：审计必须把「交互效应」和「加性效应」分开**
现有 LLM 审计大量是单因素对比，结论容易被因素间交互污染（某个改动只在特定 模型×任务 组合下有效，换个组合就反号）。对 agent 工程的提醒很直接：换 harness、换工具 schema、换上下文策略这类 A/B 必须做组合实验并报交互项，否则很容易得出「换模型没用」「加检索没用」这种错结论。
https://arxiv.org/abs/2611.26509

## ⚠️ 安全与踩坑

**「Hungry Butler Effect」：LLM 输出里可能藏着未披露的商业激励**
研究指出模型在推荐/排序类输出上可能受未公开的商业动机影响，且从表面看不出来。对 agent 的直接含义：凡是让模型做「选服务商 / 选依赖库 / 选商品」的决策，结论都要能追溯到明确规则或独立数据源，别把模型推荐直接当采购依据。
https://www.researchgate.net/publication/418143113_The_Hungry_Butler_Effect_Concealed_Commercial_Incentives_and_the_Erosion_of_Epistemic_Rigour_in_Large_Language_Models

**OpenAI：对抗蒸馏的检测与处置口径（HN 34 分）**
官方给了「用你的 API 输出训竞品」这类行为的识别与处置说明。对自建模型或对外提供 API 的团队：调用侧要留指纹与异常模式检测，蒸馏相关条款要提前写进对外协议，而不是事后追。
https://openai.com/index/combatting-adversarial-distillation/
