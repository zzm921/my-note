## 🧩 Agent 开发

**4. Coral：给 Agent 的「执行轨道」，权限精确 + 自定义工具更省 token**（Show HN 48 分/23 评）
withcoral/coral ★4985，Rust，Apache-2.0，仓库自述「Execution rails for agents」——让 Agent 对接敏感企业系统时只拿到精确权限和自建工具，工具调用更快、token 更少；卖点是 agent 可自己写工具。
接入方式：作为现有 Agent 与外部系统之间的网关层插入，替换裸 tool-calling。适合你现在就在踩的「工具太多、上下文被 schema 塞满」问题。
https://github.com/withcoral/coral

**5. Docker Sandbox Kit 规范：把 AI 智能体的权限打包成 OCI 镜像**
InfoQ 报道，该规范把 Agent 的权限/能力边界做成可分发、可审计的镜像单元。
对 Agent：跑不可信工具、shell、浏览器时，这比自建沙箱更省事——权限随镜像走，换环境不用重配。建议先在「会执行代码/命令」的那条链路上试点。
https://www.infoq.cn/article/yV89L6iMCqSLDHeSoLxo

## 📊 评测与基准

**9. 论文：验证器打的分，换个抽象层还成立吗？**
arXiv 2611.18412 提出「verification transport」：测量 LLM Agent 评测里 verifier 的判断在抽象/换环境后能否迁移。
对 Agent：如果你的评测是靠 LLM verifier 打分，换任务包装、换工具集后分数不可直接对比——这份工作给了量化方法，别再拿跨版本的 verifier 分数当回归基线。
https://arxiv.org/abs/2611.18412

**10. 论文：用机制可解释性解释 Web Agent 的元素幻觉**
arXiv 2611.18494（Aghzal、Geva、Stein、Yao）以 web element hallucination 为案例，检验机制可解释性能否定位 Agent 失败原因。
对 Agent：浏览器 Agent 最痛的「点了不存在的元素」，从「改 prompt」升级到「看内部表征」，值得作为失败归因的新工具箱。
https://arxiv.org/abs/2611.18494
