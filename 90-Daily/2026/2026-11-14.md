## 🧩 Agent 开发

**3. Claude Code v2.1.323 上线 Code Mode：让模型写 JS 调工具，取代逐个 JSON tool call**
改动点：opt-in 实验特性，模型生成一段 JavaScript 来编排工具调用（循环、条件、中间结果处理都在代码里完成），开关在 code.claude.com/docs/en/code-mode。`claude update` 或在插件里升级到 2.1.323 即可。
→ 对 Agent：这是当下最直接的降 token、降延迟路径——工具结果不再一条条灌回上下文。自研 agent 完全可以照这个思路实现一版「code-as-action」执行器，先拿一个多步检索/批处理场景对比往返次数。
https://github.com/anthropics/claude-code/releases/tag/v2.1.323

**4. Antigravity Orchestrator：同一条轨迹里动态换模型（Carbon 规划 ↔ Hydrogen 执行）**
官方给的架构结论很值得抄：静态「按首个 prompt 猜难度」的 router 在长任务上必然失效，因为不同阶段需要的复杂度不同。Orchestrator 做双向切换——Carbon 先只读探索、出计划并设重规划触发点，Hydrogen 写改动、跑测试，遇到摩擦回交 Carbon 修计划。Terminal-Bench 4.1 上接近 Carbon 成功率，配额少 24%、快 19%。要显式编排可用 Antigravity SDK：Carbon 当 coordinator，Hydrogen 当 worker/verifier 并行跑隔离工作区。
→ 对 Agent：本周最可复用的一条工程结论，多智能体 + 多模型的成本结构可以直接照抄「按阶段分工 + 摩擦回交」。
https://antigravity.google/blog/gemini-4-hydrogen-in-google-antigravity/

## 📊 评测与基准

**11. Parsed, Plausible, Wrong：输出格式会决定小模型的静默错误率**
arXiv 2611.17128。同一个语义解析任务，换输出格式就会显著改变「看起来对、其实错」的比例——错误不会报错，只会安静地错。
→ 对 Agent：工具调用/结构化输出用宽松 schema 时最危险。做小模型 function calling 的，建议先固定输出格式再比模型，别用总分掩盖解析层的静默失败。同批次 AgentSSL（2611.17316）问 MLE Agent 能否用无标注数据自我提升，数据科学类 agent 可关注。
https://arxiv.org/abs/2611.17128 ｜ https://arxiv.org/abs/2611.17316
