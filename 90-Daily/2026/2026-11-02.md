## 🤖 大模型

- **商汤开源 SenseNova Loop-9B-Preview：用「循环计算」把 9B 顶到 27B 水平**（雷峰网 10-31，已核原文）：Looped Transformer 架构，保留首尾各 4 层原始解码层，中间层改成参数共享的循环模块、多轮迭代扩展「有效计算深度」，并引入 mHC（流形约束超连接）稳住多轮之间的信号传递。
  对 Agent：参数不变、用算力换深度，适合塞进工具调用密集的单机 agent；但每步要多轮前向，时延与显存要按轮数重算——先在你自己那条工具调用链上量一版 p95 再决定上不上。
  https://www.leiphone.com/category/industrynews/f9tAHG0kPopK1Nnw.html
- **清华姚期智团队「代数世界模型」：让模型像牛顿一样做符号化建模**（量子位 11-01，按标题口径）：思路是把物理/数学规律显式写成代数结构交给模型推演，而不是只在 token 空间里拟合。
  对 Agent：做「可验证的规划器」时符号层天生可校验，比纯文本推理好做断言；但这是研究阶段，暂时没有可跑的权重，先当方向看。
  https://www.qbitai.com/2026/11/507031.html

## 🧩 Agent 开发

- **Memdoor team-solve：5 个小模型分工，LiveCodeBench Hard 上追平专用 harness**（GitHub，HN 377 分；已核 README 与结果文件）：planner + 2 个 ideator + solver + manager + repair worker，每个角色全新上下文、只通过磁盘文件通信，成败由跑 sample 的脚本判定而不是模型；整套配置就是 8 个 YAML、零代码。
  实测（10 题 ×5 次）：本方案均值 9.8/10，原论文 harness 9.6，Fable 5 单次调用 8.0；单次运行中位 40 分钟、$0.39，50 次共 $35.79。注意是 10 题小样本、题目可能进过训练集，污染排除不了，别读成「小模型 > 前沿模型」。
  https://github.com/guregodevo/memdoor/tree/main/examples/workflows/team-solve
- **DeepSeek《Super-agent》补充：投机执行 + 事件「订阅/直通」才是成本开关**（量子位 11-01，已核原文；机制昨日已报，这里只补新增）：Agent 发现群里在聊 Bug 就先在后台复现，成了才吭声、失败保持安静（投机执行）；Worker 接手某个 PR 后可直接订阅后续评论，不再经 Router 转发——关掉直通后 Router 决策次数 +30%、读缓存 token +37%。
  实测（300 条消息 / 20 个请求）：完成时间中位 12.4 分钟、p95 15.7 分钟，单会话方案 p95 29.5 分钟。对 Agent：路由设计是省 token 的第一杠杆，先把「事件该进哪个会话」做成表，再谈上下文压缩。
  https://www.qbitai.com/2026/10/506904.html
- **earshot 0.4 ★3427：给编码 agent 装「耳朵」，CLI / Python API / MCP server 三入口**（GitHub，已核 README）：把声音变成 agent 能推理的证据——文件听起来像什么、与描述匹配度打分、长录音里的最佳片段、真人录音 vs 代码合成检测、整片逐秒听觉转录、对照专业片的评分卡；`earshot forge` 还能让 agent 自己用代码造音、靠「听」迭代。纯 CPU、本地跑。
  对 Agent：这是「用 MCP 挂一个新模态」的标准姿势；你的 agent 若产出 demo / 游戏 / 视频，听觉正是它唯一缺的反馈环。
  https://github.com/Leonxlnx/earshot
- **learnharness ★4673（两周内）：把「教会一个人」做成 agent harness**（GitHub，TypeScript + Electron）：先测你会什么、怎么推理，据此规划课程，每步用你的回答决定下一步教什么，跨会话靠持久知识图谱续上。
  对 Agent：harness（工具 + 状态 + 评估回路）正在成为独立赛道；它「知识图谱当记忆、推理链当最小教学单元」的两条可以直接搬到长任务 agent。
  https://github.com/amosblomqvist/learnharness

## 📊 评测与基准

- **VeriCUA：把「验证」变成 agent 的探索行为，专评 computer-using agent**（arXiv 10-31）：不只比对终态，而是让 agent 主动验证中间状态（页面真变了没、操作真生效没）。
  对 Agent：GUI / 浏览器 agent 最容易「假成功」，这套思路可以直接转成你的回归断言——每步截图 + DOM 差异比对，而不是只看最后一句「已完成」。
  https://arxiv.org/abs/2610.40563
- **50 个 agent 在 Minecraft 里组团建文明，最后死于官僚流程**（Tom's Hardware / HN 11-01，101 分）：规模一上去，协调开销吃掉全部产出，反复开会、互相等审批，最终没建起来。
  对 Agent：多智能体的拐点不在模型能力而在协调协议——先控规模（Memdoor 那条 6 个角色跑赢），再加「谁能直接动手、谁必须请示」的硬规则。
  https://www.tomshardware.com/tech-industry/artificial-intelligence/ai-agent-swarms-unleashed-in-minecraft-to-build-a-thriving-civilization-50-agent-teams-fail-after-falling-into-paralyzing-bureaucracy

## 💰 成本与基础设施

- **赛迪：国内 AI 推理数据量首次超过训练数据量，6 月日均词元调用 175 万亿**（IT之家 11-01，已核原文）：比 2024 年初增长 1000 多倍，官方口径是「从喂模型转入用模型」。
  对 Agent：推理侧已是主战场，容量规划、缓存命中率、上下文长度这些指标比「训练卡数」更影响你的账单。
  https://www.ithome.com/1/020/809.htm
- **ChatGPT 与 Codex 的用量额度合并**（OpenAI 帮助中心 / HN 10-31）：两个产品的限额并进一套口径。
  对 Agent：拿 Codex 当子 agent 或在 CI 里自动提交的，先看清合并后是共享池还是按产品切分，再调 batch 大小与重试策略。
  https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits

## ⚠️ 安全与踩坑

- **OpenAI / 谷歌 / 微软 / Anthropic 联合推行 robots.txt 的「AI 抓取退出」标准**（IT之家 11-01，已核原文）：由 Anthropic 的 Kevin Kelley 提交 IETF，写进 robots.txt，一次声明对所有厂商生效；Anthropic 已采纳，OpenAI 数月内跟进，谷歌与微软明年。
  对 Agent：抓取类 agent 的合规基线变了，robots.txt 解析要认新字段，否则「按老规则抓」半年后就是默认违规。
  https://www.ithome.com/1/020/837.htm
- **当 AI 能读懂二进制，闭源软件还剩多少护城河**（InfoQ 11-01）：讨论 AI 辅助反编译 / 逆向对闭源交付模式的冲击。
  对 Agent：两头都要提前布局——把逆向能力接进自己的供应链审计（查依赖里有没有可疑产物），同时给自己发布的产物（WASM / JS / Electron）加混淆与反调试，别默认「编译过就安全」。
  https://www.infoq.cn/article/8mCjWWFLdjDA2vb51QZs

## 🔥 值得深看

- **Memdoor 的 team-solve 配置（8 个 YAML）**：目前见过最省钱的多 agent 编码编排——文件当共享内存、脚本当裁判，一下午能照搭一版跑自己的题。
- **DeepSeek 的「订阅/直通 + 投机执行」**：给的是可量化取舍（+30% 决策、+37% 缓存 token 换 p95 减半），比任何架构图都更值得抄进调度层。
- **SenseNova Loop-9B**：想在小显存上跑 agent 的，值得实测「循环轮数 vs 工具调用成功率」这条曲线。
