**6. 千问办公 2.0 发布 Team Agent：多人与 Agent 同处一个会话**
同一事件在量子位/InfoQ/雷锋网都上了头条：首个支持「多人 + Agent」协作的办公 Agent。工程上值得抄的是**多主体会话模型**——任务归属（谁派的）、权限（这个 agent 代表谁说话）、审计（谁批准了写入）。自己搭内部 Agent 时这三件事一开始不做，后面补代价极高。
→ https://www.qbitai.com/2026/11/508694.html ｜ https://www.infoq.cn/article/1Mz0ADa02PxcDsVfpVEb

**7. InfoQ：Anthropic 工程师谈 Agent 管理——不会当管理者就用不好 Coding Agent**
文章的核心论点：Coding Agent 的产出上限取决于你**拆任务、给验收标准、控制上下文**的能力，而不是模型多强。可操作三条：任务拆到单次可验证、把「什么算完成」写进 prompt、每轮只喂必要文件。对照自己的流程，先看失败案例是不是都出在这三点。
→ https://www.infoq.cn/article/YPQYy6bqhzhtO8MN6XUb

**8. arXiv：AI Agent 到底需要多少对话历史？（2611.09634）**
直接问上下文预算这个工程问题：全量保留、保留 N 轮、还是摘要/检索，各自的成本与效果边界在哪。这类问题的答案强依赖任务分布，别照搬结论——按自己的任务做三档对照（全历史 / 摘要 / 检索），token 成本与成功率一起记，才知道该砍在哪。
→ https://arxiv.org/abs/2611.09634

**9. arXiv：两层会话记忆——压缩、衰减、强化，与 RAG 配对评测（2611.09785）**
把记忆拆成短期层（压缩 + 衰减）与长期层（强化保留），并与 RAG 做配对对比。工程启发：记忆不是「全存 + 检索」，需要主动遗忘机制，否则旧结论会污染当前决策。实现上可以先给现有 memory 加 TTL 与命中计数，跑一周看误用率。
→ https://arxiv.org/abs/2611.09785

## 💰 成本与基础设施

**12. arXiv CPU-ARC：把推理轨迹缓存起来，在 CPU 上复用（NVIDIA）**
给 agentic reasoning 做**缓存复用**：相同/相似子问题的推理轨迹不重复算，改成在 CPU 上检索命中后直接复用。适用固定 SOP 的 agent（客服、运维、报表），重复度高、单次推理贵。先在日志里统计「重复子问题占比」，超过 20% 再谈接。
→ https://arxiv.org/abs/2611.09872

## ⚠️ 安全与踩坑

**13. ChatGPT Desktop 会把 SSH agent 转发到远端机器——远端 agent 能用你的密钥推私有仓库**
HN 181 分 / 59 评，作者给了复现：桌面端在远端跑任务时本地 ssh-agent 被转发过去，**远端机器上的 agent 因此能用你的本地 SSH 凭据认证**，示例是往你的私有 GitHub 仓库 push（附 openai/codex PR 28131 讨论链接）。这是「便利性默认值」造成的凭据越界，不是漏洞利用。
现在能做：`ssh-add -l` 看当前加载了哪些 key，跑远端/云端任务前 `ssh-add -D` 清空，或改用需要触摸确认的硬件 key；再去 GitHub 看一遍近期 push 记录。
→ https://news.ycombinator.com/item?id=50422628

**14. qybaihe/bla（★4235）：给客户端加一层「抗 AI 逆向」的对抗盾**
BLA（Blind LLM Agents）针对的是一类新对手——REA 这类**自动逆向 Agent**，能批量拆二进制、Electron、JS bundle、Python、WASM；bla 用对抗手段让自动逆向拿到错误结构。适用于前端 bundle、桌面端要发给不可信用户的场景。注意这是军备竞赛，不能替代服务端鉴权：真正的密钥永远不该出现在客户端。
→ https://github.com/qybaihe/bla
