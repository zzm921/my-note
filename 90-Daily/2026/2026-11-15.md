## 🧩 Agent 开发

- **browser-use 1.0.4rc1**：改了截图裁剪策略——不再每出新截图就清旧图，而是等 20 条工具结果后一批丢掉。原因是每次裁剪都要重写早期消息，会打断 provider 的 prompt cache，截图多的任务反而更贵。`pip install 'browser-use==1.0.4rc1'`。→ 这条经验可直接搬给任何多模态 agent：消息历史尽量只追加、不改写。
  https://github.com/browser-use/browser-use/releases/tag/1.0.4rc1

  https://www.oschina.net/news/503576

## 🔥 值得深看

1. **Claude Code Projects 重设计（coordinator → 并行 threads）**：你提需求，Claude 负责拆解、派活、协调并行线程、审结果并汇总；每个 thread 还能再用 subagent / loop / workflow 继续细分，撞车按 PR 合并冲突处理；coordinator 和各 worker 的模型、effort 可分别设，目前跑在云端。原文 9-17 发布，昨天被 HN 重新热议（95 分 / 90 评）——是当下「多智能体编排」最完整的一份产品化样本。 https://claude.com/resources/articles/projects-redesigned
2. **browser-use 那条 prompt-cache 教训**：任何「为省 token 去改写历史消息」的优化都可能让 provider 缓存失效，净成本反升——值得回头检查自己 agent 里的历史裁剪逻辑。
3. **CoReMem**（arXiv 2611.17309）：把记忆成本内部化，给连续编码任务做带价值评估的记忆管理。→ 长任务 agent 的「记什么、何时忘」终于可以用预算模型来算，而不是拍脑袋定 top-k。
