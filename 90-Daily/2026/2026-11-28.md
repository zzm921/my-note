## 🧩 Agent 开发

**MCP 官方 servers v2.6.0：一次修 8 个漏洞，含 git server 可被仓库配置触发执行程序**
`mcp-server-git` 的 Git LFS 会执行仓库 `.git/config` 里指定的程序（`lfs.extension.*.smudge/clean`、`lfs.customtransfer.*.path`），连只读的 `git_status`/`git_diff` 都能被利用；`--repository` 根目录还可被指向另一个仓库，`git_show` 会读到别人仓库的内容。受影响：mcp-server-git ≤2026.11.18、server-memory 1.0.0–2.2.1、mcp-server-fetch 2026.10.10–2026.11.18、Windows 上 server-filesystem ≤2.4.0。
今天就能做：`mcp-server-git`→2026.11.27、`@modelcontextprotocol/server-memory`→2.2.2、`mcp-server-fetch`→2026.11.27、Windows 上 `@modelcontextprotocol/server-filesystem`→2.4.1。
https://github.com/modelcontextprotocol/servers/releases/tag/v2.6.0

**JioHotstar 实测六种「给编码 Agent 装知识库」方案：加检索层不一定更准，也不一定更省 Token**
对比文件系统工具、Sourcebot、Graphify、CocoIndex Code、Repowise 与自研 RAG 管线，跑 SWE-bench Lite/Verified + CodeScaleBench + 自建问答集，解题模型 Claude Sonnet，指标含准确率、Token、交互轮数与工具易用性。
结论：目标明确的任务里「文件系统 + 搜索」基线仍有竞争力；Sourcebot 在 SWE-bench Verified 上超过基线且更便宜；简单任务加检索只是多花 Token；需求模糊、跨模块（CodeScaleBench）才轮到语义检索。Agent 天然偏爱 grep / 读文件 / 找符号，高层抽象工具反而少用。
对 Agent：别急着上向量库——按任务类型分流检索策略，并把「工具调用轨迹」纳入评测，而不是只看通过率。
https://www.infoq.cn/article/Ql4GGMIEqA3bI2W2lh7h
