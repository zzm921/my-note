## 🧩 Agent 开发

**Google Workspace 八个 MCP server 正式 GA，同时立规矩：2027-02-01 起 AI Agent 必须走 MCP**
新增《Workspace AI Tools Addendum》：由 AI Agent / 模型驱动的工具必须经 Google MCP 访问 Gmail、Drive、Calendar 等，绕开或伪装成非 Agent 会被限流甚至封号；同日起 Agent 直连 REST API 一律按 Standard 档配额算，付费档不顶用（确定性脚本、CRM 同步不受影响）。
坑在细节：Gmail MCP 只能搜/读/建草稿/打标签，**发信、回复、转发属 partner-only**，带附件草稿尚不支持；Workspace 数据只许用于「用户主动授权的任务」，用户断开即须删除，而向量嵌入、记忆索引、用户画像这类衍生数据最长保留被压到 30 天，且禁止用于训练/微调/评测/蒸馏。
对 Agent：现在做三件事——盘清哪些集成直连 REST（两个月内改 MCP）、把长期记忆索引从「永不过期」改成可重建的 30 天滚动索引、给发信类动作留人工确认或申请 partner。
https://techstackups.com/articles/google-workspace-ai-agents-mcp/

**llama.cpp v1.1.0：server 内建 Agent 形态（agent traces / MCP 代理 / 具名 tool_choice）**
新增 `--ui-agent` 与 `--ui-mcp-proxy-allow-private-urls`（Web UI 里直接跑 Agent 并挂 MCP，默认只许公网 URL，要打内网服务得显式放开）；聊天界面重做，支持语音消息与 **agent traces**；server 接受 OpenAI 风格具名 `tool_choice`，单模型模式加 `GET /models/sse`；量化侧加 `--target-bpw` / `--target-size` 按预算自动选每张量精度（带可续跑 state 文件）。
破坏性变更：旧 `llama_batch` C API 弃用，改 `llama_batch_ext` + `llama_process`；DFlash 投机解码拆成 draft-dflash / dflash2 / dspark / lilicorr 四档；新增 Inkling 2、Hy4 flash（220B / 12B 激活）、RAON-1-mini（30B-A4B）与 Kyutai Hibiki 全双工语音。
对 Agent：本地栈想少写胶水代码，直接用 `llama-server --ui-agent` 起验证环境；绑了 C API 的项目这两天就得跟 `llama_batch_ext`。
https://github.com/ggml-org/llama.cpp/releases/tag/v1.1.0

**openai-python v3.60.0：API 侧加了 spend alerts 与 response compaction 字段**
SDK 更新里最值得注意的两项是「花费告警」与「响应压缩（response compaction）」相关字段——后者意味着上下文压缩开始由服务端参数化，而不是全靠客户端裁历史。
对 Agent：`pip install -U openai` 后在请求里显式打开压缩/告警字段，先在一个长会话 Agent 上对比 token 账单与压缩后的事实召回，再决定是否替换自研压缩器。
https://github.com/openai/openai-python/releases/tag/v3.60.0

**arXiv《TASK Memory》：把「记忆幻觉」放到激活层和知识编辑层修**
不再只靠「检索—拼接文本」，而是用激活引导（activation steering）加知识编辑纠正记忆里的错误事实，针对长程 Agent 把旧信息说成新事实这类问题。
对 Agent：如果你的记忆模块是「向量库 + 摘要」，这篇给的是第二道闸——写入时先做事实一致性校验，冲突时走编辑而非追加。
https://arxiv.org/abs/2611.34751

**OpenHands v1.46.0：会话可按团队/组织列出与取消共享**
开源编码 Agent 平台这次发版主线是协作权限：会话共享支持团队组织维度，可列出、可撤销（OHE-4205）。
对 Agent：多人共用一台 Agent 工作台时，这是「谁能看到哪次运行」的最小实现，权限模型可直接参考；升级用官方镜像 tag v1.46.0。
https://github.com/OpenHands/OpenHands/releases/tag/v1.46.0

## 📊 评测与基准

**DRBench Pro：面向「专业深度研究 Agent」的知识密集型基准**
arXiv 2611.34832，把深度研究拆成需要跨源取证、术语正确、结论可核验的任务，而不是开放式问答打分。
对 Agent：做研究报告类 Agent 的，可用它替代「让 LLM 给自己打分」，重点抄它的评测项设计（证据链是否可追溯）。

**μ-Bench：共享交互场景下的多用户语音 Agent 基准**
arXiv 2611.34852，考同一次语音会话里多人轮流说话、任务状态要跟着切换——现有语音 Agent 基准基本是单用户。
对 Agent：端侧语音入口正从手机扩到手表/眼镜（雷锋网同期在讨论「随身感官」），多说话人 + 抢占式打断会是必答题。
https://arxiv.org/abs/2611.34852

## ⚠️ 安全与踩坑

**0.1% 的预训练数据污染，就能给 Agent 埋下「洗不掉」的后门**
开源中国转述的研究：极小比例投毒数据进入预训练后，后续安全对齐也难清除，触发条件命中即执行攻击者行为。
对 Agent：凡接第三方权重、社区微调版、来路不明的 GGUF，都按「可能带后门」处理——工具权限最小化、危险动作走审批，别把宿主机权限直接交给本地模型。
https://www.oschina.net/news/503823

**自托管 ≠ 不出网：Cohere 研究 + T3 Code 被指收集数据**
Cohere 的结论是开放权重模型自托管后仍需做出站控制（模型与依赖仍会外联）；同期开源 AI 编程工具 T3 Code 被扒出收集用户数据。
对 Agent：给本地 Agent 加 egress 白名单（只放行必要 API 域名），接入任何「开源」编码 Agent 前先抓一遍它的 telemetry 上报。
https://www.infoq.cn/article/bzWoHP0FGUBSTBuP5xVJ
