## 🧩 Agent 开发

- **vLLM 工具调用准确率 92% → 100%：问题在推理引擎而不在模型**（Ubicloud 博客，HN 116 分，10-26，已抓全文核实）——自托管 Kimi K2.6 / DeepSeek V4 Flash 时，工具调用不符合 schema 会**把错误信息灌进上下文并触发重试**（双重成本）。修法是开启 vLLM 的 **constrained decoding**（底层 XGrammar 的 structural tags + `JSONSchemaFormat` 约束参数 JSON），在 Moonshot 的 K2VV ToolCall 基准上把 schema accuracy 从 **92% 拉到 100%**。今天就能做：为每个工具声明严格 schema 并打开 guided/constrained decoding，把「工具调用失败率」当成推理服务的上线指标。
  https://www.ubicloud.com/blog/fixing-tool-call-accuracy-in-vllm
- **投研 Agent 两年演进：删掉 cleaner.py 与 387 条信源名单，交给一个检索接口**（InfoQ 10-26，已抓全文核实）——可直接照搬的设计：检索参数 **Mode 0/1/2**（公开网页 / 优质垂直信源 / 混合）+ **Industry** 领域限定；**Site** 每次指定 1 个域名、排除最多 5 个域名（仅作用于公开网页结果，原白名单不能直接等价为一个参数）；**Freshness** 支持 `d1/d2/m3/d7` 与日期区间，结果带 **date**；每条结果给两个独立信号 **score（0-1 相关度）** 与 **authority_level（0-5 权威度）**。两个坑：**「多条结果 ≠ 多个独立来源」**（同一新闻几十个转载会被误当交叉印证，AI 生成内容与 GEO 在放大噪音）；站点侧把几千 token 网页压成约 **100 个 Gist token** 缓存，推理成本省约 **30%**。价格：极速/标准/旗舰 14/20/26 元每千次（旗舰限企业，邀请码送每月 6000 次）。
  https://www.infoq.cn/article/NrUkJExfuuFOICsjVYbb
- **openai-python v3.38.0**（10-26）：新增 **delegation controls 与 prompt cache lifetimes**（release 摘要口径）。对多 Agent 编排的意义：**子任务委托策略**与**缓存存活时间**开始进入官方 SDK 的显式开关，正好是「可控性」与「成本」两项。升级：`pip install -U openai==3.38.0`。
  https://github.com/openai/openai-python/releases/tag/v3.38.0
- **PaperPilot（HN 218 分，10-26）：纯 Rust、零云依赖的 PDF 引擎，带 WASM 与 MCP**——把 PDF 解析全部放本地，再以 **MCP** 暴露给 Agent，文档不出机器。适合做本地文档 RAG / 合同票据类 Agent 的工具层，可直接作为 MCP server 挂进现有 harness。
  https://github.com/KrushnaVardhanReddy/PaperPilot
- **ToolForge v0.2.2**（开源中国 10-26）：让 Agent 调用工具，支持 **MCP、CLI 与插件级权限管理**——权限按插件粒度收口，是给自主 Agent 补最小权限边界的一块拼图（列表页标题口径，未取正文）。
  https://www.oschina.net/news/503201

## 📊 评测与基准

- **K2VV ToolCall（Moonshot 发布，本次经 Ubicloud 实践侧核实用法）**：**2000 条请求**，两个指标——**trigger similarity**（该不该触发工具调用，与官方服务的一致性）与 **schema accuracy**（调用是否符合 schema、能否真正执行）。建议：上线前用它测自己的推理服务，把「工具调用成功率」做成回归项；schema accuracy 50% 就意味着**一半工具调用是坏的**。
  https://www.ubicloud.com/blog/fixing-tool-call-accuracy-in-vllm

## 💰 成本与基础设施

- **价格战背后的真实账单结构：coding agent 96-99% 的 token 支出是「缓存读」**（Max Woolf 10-25 分析，已抓正文）——近几个月 OpenAI/Anthropic 多次降价（Luna 一次降 **80%**、Sol 降约 20%、Fable 5.1 的**缓存读降到 1/4**）。关键结论：Agent 缓存命中率通常 90-100%，**缓存读单价降 75% ≈ 整体使用成本降 70-75%**。今天就能做：把「缓存命中率 + 缓存读单价」放进成本看板首位，稳定提示前缀（别让每轮变化的文本插在前面）比换模型更省钱。
  https://minimaxir.com/2026/10/cheap-llms/

## ⚠️ 安全与踩坑

- **开放权重模型的攻防能力正被主动裁剪**（开源中国 10-26：Kimi K3.1 Pro 开放权重版移除网络攻防能力），同时 GitHub 近 30 天热 repo 里出现 AI 自主渗透测试框架 **ARTEX**（★2214，AGPL-3.0）。动作：① 接入任何安全/红队类开源模型或工具链前，先跑自己的能力边界测试（上游行为可能已变）；② 把工具权限收到插件/命令粒度（参见 ToolForge 那类权限管理）。

## 🔥 值得深看

- **自建推理栈先开 constrained decoding**：92% → 100% 的经验说明「模型没问题、服务有问题」是常态；坏调用既污染上下文又要重试，成本双损——今天就给自托管模型加上严格 schema 约束。
- **把缓存命中率设成核心成本指标**：缓存读占 coding agent 支出 96-99%，缓存读降价 75% ≈ 总成本降 70-75%；稳定提示前缀 + 控制缓存 TTL（openai-python 3.38 已把 cache lifetimes 放进 SDK）比换模型更直接。
- **检索层是 Agent 现在最该外包的一层**：投研 Agent 用两年删掉 cleaner.py 与 387 条信源名单；Mode/Site/Freshness + score/authority 两级信号，可以直接照搬进你自己的检索抽象。
