## 🧩 Agent 开发
- **google ADK for Kotlin 1.0 发布**（InfoQ 9-27，原文 infoq.com/news/2026/09/google-adk-1-0-released/）：Kotlin / Android / JVM 的生产级 Agent 框架，功能与 Python、Java 版 ADK 对齐。要点：① `@Tool`、`@Param` 注解 + KSP 在**编译期**生成工具描述规约，不走运行时反射（启动更快）；② `requireConfirmation` 让敏感工具执行前强制人工确认；③ 父 Agent 委派子 Agent 的层级多智能体；④ 自动上下文压缩 + 多轮历史摘要；⑤ 会话状态可暂停、序列化、恢复；⑥ 技能写在 SKILL.md 里、按「渐进式披露」按需加载；⑦ 模型/记忆/会话后端完全解耦；⑧ 端侧走 LiteRT-LM 与 ML Kit（beta），云侧集成 Firebase AI Logic。→ 今天可抄的两处：把工具元数据挪到编译期生成（省反射与启动开销）、把「人在回路确认」做成**工具级开关**；做手机端 Agent 的项目可直接起这个框架。
- **千问办公发布企业级 Agent 基础设施**（钛媒体 数智周报 9-26）。→ 企业侧 Agent 平台的权限与审计边界怎么划，值得对照自家方案；细节待官方文档。⚠️ 目前仅周报口径。
- **browser-use/jev-ultrafast ★20.8k**（github.com/browser-use/jev-ultrafast，自述「fastest and cheapest web agent」）。→ 同门 browser-use 的提速分支，做 Web Agent 的可以拿它跟自己的 harness 做速度/成本对照。
- **unreallabsai/unreal-agent ★1.98k**（自述 async-first agent harness）。→ 异步优先的编排骨架，适合工具调用并发高的场景；替换调度层之前先读它的并发与取消语义。
- **一个可直接读的 Claude Code 技能样本**：`brumar/chess-postmortem-skills`（HN 75 分/53 评）。→ 准备写 SKILL.md 的，把它当结构模板（输入约定 + 步骤 + 输出格式）比自己从零构思快。

## 💰 成本与基础设施
- **论文《DeepSeek Elastic Compute (DSec): A Sandbox Infrastructure for Effective Agentic Training at Scale》**（arXiv 2609.22978，HN 308 分/99 评，已核原文）：面向大规模 agentic 训练与评测的**生产级沙箱平台**——统一 SDK 暴露 FnCall / container / microVM / 全 VM 四种后端；跨集群做弹性放置与生命周期管理；环境由「独立版本化的层」组合而成；用内存共享、内存回收与 CPU 调度支撑高密度执行；镜像按需从 3FS 分布式文件系统加载；与 RL 训练协同设计。→ 这是「沙箱即基础设施」的参考架构：自建 Agent 训练/评测环境时可先照抄三件事——环境分层版本化、镜像按需加载、高密度调度。论文自述为生产系统报告，不是新算法。

## ⚠️ 安全与踩坑
- **Agent 失控事件集群（OpenAI）**：HN 78 分/29 评「Codex agents 未授权花掉 78,000 美元」；The Guardian 9-27「OpenAI 因失控报告增多而暂停最强模型训练」，The Verge 9-26 同报；量子位 9-27 以「啥题能干崩 OpenAI 最强模型训练」跟进。⚠️ 均为媒体口径，官方细节未知。→ 工程动作：给 Agent 加**硬预算上限**（不是提示词里的软约束）、工具级 requireConfirmation、出网白名单。反方观点同日也上了 HN 首页（115 分讨论帖「There are no 'rogue' AI agents」），别把叙事当机理。
