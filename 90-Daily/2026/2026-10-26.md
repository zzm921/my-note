## 🤖 大模型

- **社区自测：Qwen3.8-27B 组合在 LiveCodeBench Hard 上追平 Claude Fable 5**（HN 10-25 头名，177 分 / 64 评）——仓库 **slee-persis/GVS5H**（MIT，★947）自述为「五个 Qwen3.8-27B 模型配一套 harness，以 1/5 的价格、甚至**单卡**达到 Fable 5 级编码」。⚠️ 项目方自测、非第三方复现，仓库最后更新在 9 月下旬，本周热度来自讨论。对 Agent 的意义：**编码类 Agent「规划用贵模型 + 执行/修复用本地 27B」的分层路线有了可对照的公开方案**，值得先读它的 harness 与评测口径再决定是否复刻。
  https://github.com/slee-persis/GVS5H
- **韩 KRAFTON AI 预览 Raon-1 mini：30B-A4B**（IT之家 10-25）——MoE 架构，总参 30B / 激活约 4B，官方口径对标 Meta Muse Glimmer。这类「大总参 + 小激活」是小团队自托管的现实选择：显存按总参算、算力按激活算，适合放进 Agent 的**路由/抽取/子任务执行**这一层；上线前先按并发与显存预算算清单卡能跑几个实例。
  https://www.ithome.com/1/017/695.htm
- **arXiv：Direct Pass@k Optimization for Thought Pruning**（2610.31650，题名即方法要点）——把 **pass@k 目标直接纳入优化**来做思维剪枝，在「答案质量」与「候选多样性」之间做显式权衡。落到 Agent：长链推理里冗余思维链是 test-time token 成本的主项，这类剪枝口径可直接用在你的**推理预算控制器**（think token 上限、多候选采样的取舍）上。
  https://arxiv.org/abs/2610.31650

## 🧩 Agent 开发

- **modelcontextprotocol/servers v2.1.0（10-25 发布，已抓 release 正文核实）——本批必升级项**：一次修掉 **8 个漏洞**，涉及三个官方服务端；升级写死在版本上：`npm install @modelcontextprotocol/server-filesystem@2.0.1`、`npm install @modelcontextprotocol/server-everything@2.0.1`、`mcp-server-fetch` 升到 `2026.10.24`。修复的正是 Agent 最要命的边界——filesystem 的**符号链接竞态**（校验与写入之间父目录被换成 symlink，可把 write_file / edit_file / create_directory / move_file 目标重定向到白名单外，**Windows 上仅部分修复**）、路径校验与实际使用不一致、大小写不敏感卷上的 symlink 绕过、`list_directory_with_sizes` 泄露目录外文件元信息；everything 的 **HTTP/SSE 传输不再返回 `Access-Control-Allow-Origin: *` 并校验 Origin**（此前用户随手访问的网页就能调用你本地 MCP 工具如 `get-env` 并读走结果）；fetch 修了 **IDNA 主机名校验与连接不一致**、**NAT64 地址**绕过内网拦截、**robots.txt 重定向后未复查**。**坑**：TS 服务端从日期版本改为语义版本后，包管理器**不会**把 2.0.1 当升级项（排序低于所有 2025.x/2026.x），必须显式指定版本安装。
  https://github.com/modelcontextprotocol/servers/releases/tag/v2.1.0
- **QingYunA/answer-me-with-html（★4419）**：一个 Agent Skill——**让 Agent 用一页 HTML 回答复杂问题**。接入方式就是放进你 Agent 的 skills 目录（Claude Code 这类客户端直接可用）；对「终端里读不下去的长答案」是现成解法，也可只借它的输出规范：长结论 → 单文件 HTML（可离线打开、可打印）。
  https://github.com/QingYunA/answer-me-with-html
- **Leonxlnx/earshot（★2766）**：给 coding agent 加「耳朵」的开源件，**CPU-only**，自述让 AI 能听、能回听、能发声。适合做**长任务完成/失败的声音提示**，或给语音前端做本地音频前处理；纯 CPU 意味着能与你现有 Agent 进程并排跑，不抢显卡。
  https://github.com/Leonxlnx/earshot
- **Making My Blog Readable by AI Agents**（HN 10-24）：一篇把个人站点改成**对 Agent 可读**的实践（结构化、可抓取、给机器入口）。做 Agent 工具链的人反过来也要做这件事——**你的文档站和工具说明是给别的 Agent 读的**：把「怎么调用 / 参数 / 示例」写成纯文本或结构化页，去掉必须登录、必须 JS 渲染的路径。
  https://deallocatedobjects.com/posts/making-my-blog-readable-by-ai-agents
- **Show HN: Farol（10-25）**：把 **PR 变成一张「风险地图」，给审批人而不是作者看**——按风险点组织而非 diff 顺序。做 coding agent / 自动提 PR 的可以把它接在「提交前自检」环节：**产出面向审批者的风险摘要**，而不是又一份变更说明。
  https://github.com/winnin/farol

## 📊 评测与基准

- **Linux 基金会报告《Navigating Open Source Software Development in the Generative AI Era》**（10-20 发布，InfoQ 10-25 详述，已抓正文核实）：编码任务平均耗时降 **52%**；但维护者估计收到的 PR 里约 **25% 属低质量「AI slop」，大型项目升到 31%**；贡献量在 59% 的项目上增长（大型项目 69%）；**21% 的受访者认为复杂任务反而更慢**。工程动作：给 Agent 提 PR 加**质量门**（自动测试 + 「为什么这么改」的证据链）与面向维护者的摘要，否则效率红利会变成审查负担。
  https://www.infoq.cn/article/9TSuUDxrUSGS26XTA2yB
- **EpiSEM-Bench（arXiv 2610.31593）**：专门评测 **LLM Agent 在证据缺失下的安全性与证据恢复能力**——即检索不到依据时会不会硬编、能不能回头补证据。做 RAG / 研究型 Agent 的，把「无证据场景」加进回归集：**故意删掉关键文档，看它是否承认不知道**。
  https://arxiv.org/abs/2610.31593
- **10 年前的 CNN 在皮肤癌诊断上胜过前沿 LLM**（HN 10-25）：专域小模型仍强于通用大模型。选型提示：**先区分「专域窄任务 vs 通用任务」**——Agent 里那些重复、可标注、判定标准明确的子任务，专用小模型或规则常常比再调一次大模型更准也更便宜。
  https://lynchlab.net/llm-skin-cancer

## ⚠️ 安全与踩坑

- **模型来源的供应链风险**（同一条钛媒体周报，10-25）：**美国国土安全部正式下令禁采 DeepSeek**（周报口径，⚠️ 未核实原文；同类限制近期在多地出现）。工程动作是**把模型供应商抽象成可替换层**：Agent 的 provider/适配器与提示模板里不要硬编码具体模型名与端点，为「同一任务换模型」留一个开关——合规边界一变，业务代码不用动。
