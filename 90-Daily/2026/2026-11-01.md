## 🤖 大模型

- **蚂蚁 inclusionAI 给 ZwZ2 补上 GGUF：27B 视觉语言模型 + Apache 2.0**（HF 镜像 10-30，已核模型卡）：27B / 9B / 4B 三档量化同日上传，27B 为 image-text-to-text，许可 Apache-2.0，配套技术报告 arXiv 2610.37037。对 Agent：本地多模态「读屏幕 / 读图表」这一环终于有可自托管的宽松许可选项——4B/9B 用 llama.cpp 或 Ollama 就能跑，27B 适合当单机 agent 的视觉前端；但 27B GGUF 目前仅 605 次下载，生产前先用你自己的截图/票据集验一遍。
  https://hf-mirror.com/inclusionAI/ZwZ2-27B-GGUF
- **Multi-View MoE：让每个 router 各带一个「视角」参与专家计算**（arXiv 10-31）：把单一 token→expert 路由扩成多视角路由，让路由本身参与决定专家怎么算，而不是只做分发。对 Agent：MoE 结构改动会直接改长上下文的吞吐曲线和工具调用的稳定性——这类权重通常要等 vLLM / SGLang 跟进才能吃到，看到权重前别改推理栈的假设。
  https://arxiv.org/abs/2610.40576

## 🧩 Agent 开发

- **DeepSeek 发布《Super-agent 设计探索》：Router/Worker 双层 + 事件驱动 + 异步 ReAct**（IT之家 10-31，已核原文）：Router 承接人类交互、维护全局上下文并分派任务，Worker 在隔离会话里并发执行且只向 Router 回报；外部事件（群聊、邮件日程、PR 评论、CI 结果）作为 Trigger，先程序规则粗筛、再由模型判断是否行动；上下文用 Inline & Spill（近期信息进窗口、超预算的留窗口外按需读）+ Chain of Recall（沿 Trigger/Thread/Session 引用链回捞历史）；耗时工具调用改成异步 start()/stop()，后台结果作为新事件回流（已在 DeepSeek Harness 实现但默认关闭）；计算与状态放云端、执行环境留在本地（BYOM，本地只跑轻量 daemon）；另有独立 Watchdog Session 判断 Worker 是否真的在推进。对 Agent：这是把「单会话 agent」升级成「常驻多任务协作者」最完整的一份公开设计，可直接照抄三样东西——会话对象模型、上下文分级、执行环境与状态解耦。
  https://www.ithome.com/1/020/615.htm
- **openai-python v3.42.0：agent context compaction 进 API 层**（GitHub 10-31）：Release 明确新增 “agent context compaction settings”，上下文压缩从「自己写摘要」变成客户端可配的能力。升级：`pip install -U openai==3.42.0`。对 Agent：长任务跑久了必然撞窗口，先看这组参数能否替掉手写的 summary/滑窗逻辑，能省一层自研维护。
  https://github.com/openai/openai-python/releases/tag/v3.42.0
- **claude-code v2.1.316：关掉 ultrathink 的开关 + 组级预算**（GitHub 10-31）：新增 `CLAUDE_CODE_DISABLE_ULTRATHINK`（禁止 ultrathink 关键词触发深思考，省 token 与时延）；Claude apps gateway 新增 pooled group budgets——一个组共享的月度预算，叠加在成员个人额度之上。升级：`npm i -g @anthropic-ai/claude-code@2.1.316`。对 Agent：昨天报的 2.1.313 后门事件后，停在旧版可直接跨到 2.1.316；跑在 gateway 上的团队，用组预算给「agent 自动跑」单独圈额度，别和人混用。
  https://github.com/anthropics/claude-code/releases/tag/v2.1.316
- **腾讯混元 Hy-Memory ★1899：给 agent 的双系统认知记忆引擎**（GitHub，PyPI `hy-memory` 2.0.8）：按场景拆三条记忆管线——Chat 走分层长期认知记忆，Working 走「事实 + 可复用经验」两层，Coding 用版本演化 diff-chain 追代码变更；配套 MemHub 是本地优先的桌面/CLI，把 Claude Code、Cursor、Codex、OpenCode、Qwen Code 的会话与编码轨迹汇到同一本地目录做跨应用召回；模型 Hy-Memory-30B-A3B 已开源 FP8 / GGUF 版本。对 Agent：记忆层别再手搓，`pip install hy-memory` 就能接，Coding 那条 diff-chain 尤其值得抄进自己的代码 agent。
  https://github.com/Tencent-Hunyuan/Hy-Memory

## 📊 评测与基准

- **CMB：编码 agent 的「长程 + 交错」记忆基准**（Hy-Memory 仓库，ICLR 2027 投稿中）：不测单轮问答，测长周期、多任务交织时记忆还找不找得回来。对 Agent：你验记忆层多半只看召回率，CMB 这类长程交错设定才对应真实工况，拿来当回归集比自造十个 case 靠谱。
  https://github.com/Tencent-Hunyuan/Hy-Memory
- **Pre-Crime for Agents：被「招募」的 agent 何时临门倒戈**（arXiv 10-31，按标题口径）：给 agent 在外部诱导指令下的失守点做探针式评估。对 Agent：注入防御最大的问题是没法量化，这类探针可以借来给自己的 agent 做红队回归——尤其是既读外部内容、又能调工具的那类。
  https://arxiv.org/abs/2610.40578
