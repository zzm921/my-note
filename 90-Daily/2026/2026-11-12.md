## 🧩 Agent 开发

**3. MCP servers v2.4.0：三个 server 修了六个漏洞，必须升级**
官方 release 写明 v2.4.0 修了三个 server 的六个漏洞：`@modelcontextprotocol/server-filesystem` 升到 2.3.0，`mcp-server-git` 与 `mcp-server-fetch` 升到 2026.11.11。
对 Agent 开发：这三个是最常见的本地 MCP server，等于把文件系统/Git/网页抓取直接挂在 Agent 上；今天就把锁文件里的版本对齐，并检查自己的 wrapper 有没有绕过新版校验。
→ https://github.com/modelcontextprotocol/servers/releases/tag/v2.4.0

**4. browser-use 1.0.2rc1：`--cli-mcp` 可自驱 Chromium，普通安装仍是 1.0.1**
RC 说明明确：`pip install 'browser-use==1.0.2rc1'` 才拿得到，不 pin 还是 1.0.1。新增点是关掉 Chrome remote debugging 后，`--cli-mcp` 会自己拉起 Chromium 并把状态告知模型。
对 Agent 开发：省掉「先手工开一个带调试端口的 Chrome」，容器/CI 里跑浏览器 Agent 少一个外部依赖；RC 标签说明 API 还会动，生产继续 pin 1.0.1。
→ https://github.com/browser-use/browser-use/releases/tag/1.0.2rc1

**5. OpenHands v1.39.0：automation 面板可按 owner 过滤，新增 Service accounts 选项**
release 的 Features 第一条即 `feat(automations): filter the dashboard by owner with a Service accounts option`。
对 Agent 开发：多人共用一套 automation 时终于能分清「谁的定时任务」；无人值守任务改用 service account 跑，也更容易做最小权限。
→ https://github.com/OpenHands/OpenHands/releases/tag/v1.39.0

**6. Cloudflare 推出面向 AI 应用的 Web Search API**
InfoQ 报道 Cloudflare 上线给 AI 应用用的 Web Search API。
对 Agent 开发：等于多一个「不用自己维护爬虫+索引」的检索工具层，封装成 MCP tool 或 function tool 都行；接入前重点看返回结构（摘要还是全页）是否适合直接进上下文，以及每千次调用的定价，国内访问延迟要实测。
→ https://www.infoq.cn/article/SgXuVvzbHr8lKrihTAZW

**7. Snowflake 的上下文治理实践：Harness 动态裁剪 + 业务上下文前置注入**
InfoQ 技术趋势长文，可操作性最强的一篇：CoCo 的 Harness 不预先加载全部工具定义，按任务动态发现工具；互不依赖的工具调用合并成一次调度，结果一并回传；工具输出压缩、大结果按需回源。内部 SQL 修复基准（三次重复）里 Sonnet 5 的 CoCo 通过率 86%，Claude Code 配 Opus 5 是 72%，单次报告成本 $0.446 → $0.298（-33%）。
对 Agent 开发：这就是「上下文膨胀」的标准解法清单——延迟加载工具（tool search / deferred tools）、批处理独立调用、结果摘要+原文留指针。今天就能在自己的循环里加这三条，通常比换模型更省钱。
→ https://www.infoq.cn/article/iaCUbU8Fwz6G6bDlQ9BV

**8. GitHub：40% 的 PR 已由 Coding Agent 起草，PR 流程要变成可配置**
GitHub 负责人 Jay Parikh 在 Latent Space 访谈中称 PR 不该是所有项目的必经环节；GitHub 数据是 9 月超 40% 的 PR 首版由 Agent 起草，3 月只有 17%（半年约 6 倍）。同场提到 Copilot Harness/Fusion 按任务选模型，以及 Session continuity 支持在 App、VS Code、CLI、网页间接续同一个云端 Agent 会话。
对 Agent 开发：两个可抄的点——「按任务难度路由模型」（Fusion Max 与 Opus 5.5 Max 分差 <2 分，成本约一半、耗时少约 40%），和「会话续跑」（session id 持久化 + 工作区快照），后者是自建 coding agent 最容易被忽略的一环。
→ https://www.infoq.cn/article/x0B056QFxzYEewT1Et34

**9. arXiv ReTrace：把会用工具的 Agent 蒸馏成「无 planner 工作流」**
论文提出把带工具调用的教师 Agent 轨迹蒸馏为固定工作流，推理时不再需要规划器逐步决策。
对 Agent 开发：如果线上 80% 请求走的是那几条固定路径，这就是把「每步一次 LLM 调用」压成「一次调用 + 固定工具序列」的路线，延迟和成本能降一个量级；先在高频、低变异任务上试点。
→ https://arxiv.org/abs/2611.14487
