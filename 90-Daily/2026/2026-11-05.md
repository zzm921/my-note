## 🤖 大模型

- **arXiv《You don't need long context》（2611.05306）**：实测前沿开源权重模型，后段 token 的生成成本可达前段的 7 倍；用高频 compaction 把上下文一直压在短窗口，在长程与长输入任务上准确率几乎不掉，甚至在长程 SWE 任务上「每个上下文只做一个动作」也不崩，据此提出 semantic state space models（SSSM）。
  对 Agent：这是「压缩 > 扩窗」的直接依据——预算花在摘要与状态落盘上，比买 1M 上下文更划算。落地把「每轮结束写状态、下轮只喂状态」当默认循环。
  https://arxiv.org/abs/2611.05306
- **MIT CSAIL 用 GPT-6 Astra 直接改 Qwen3.5-0.8B 权重（雷锋网 11-04）**：只动约 0.016% 参数，MATH-500 从 7.9% 提到 48.1%（≈6×）；同组实验里 Astra 仅凭权重认出 4 个游戏网络、还能从零写出可玩的权重，作者称之为 Weight-Space Programming。⚠️ 同一批「权重读写」结果前一天在 HN 被批「有误导性」（honnibal.dev），结论仍需独立复现。
  对 Agent：机制可解释性从「解释」变成「可执行编辑指令」——若坐实，修 agent 的重复循环、格式崩坏可以不打补丁、不重训，直接定位参数；目前只在小模型 + 明确任务上验证，别进生产链路。
  https://www.leiphone.com/category/ai/0F072La1etrUN0Tr.html

## 🧩 Agent 开发

- **Dify 1.19.0（11-04）**：嵌套 workflow tracing 落地——外部 trace（Langfuse 等）现在能看到 Workflow Tool 内部每一步及其 LLM 调用，prompt/response、token 用量、失败调用都保留在调用树里；同时 Workflow Tool 可随 App 包导出、新增 Skill Hub 自动化，插件 daemon 升到 0.6.14-local。
  对 Agent：多级调用「父流程 → 子 workflow → 工具」时，原来 trace 断在 Tool span；升级后能直接定位是哪一层子流程慢/贵。升级前备份 DB，按官方 upgrade guide 走。
  https://github.com/langgenius/dify/releases/tag/1.19.0
- **Claude Code v2.1.318（11-04）**：一排 MCP 与并发写的老坑被修——stdio MCP server 的版本探测失败不再每次重探（自杀式退出的 server 固定用 legacy handshake 7 天）；`claude mcp add/remove` 现在会等配置文件锁或直接 exit 1；修了「权限提示弹出前敲的键被当成回答」「`--continue` 在工具调用重试耗尽后丢历史（2.1.314 回归）」「idle compaction 用非摘要内容替换对话」。
  对 Agent：自建 MCP 客户端可照抄三条——server 健康探测要缓存失败结果、配置写入必须加锁、会话压缩要校验输出确实是摘要。
  https://github.com/anthropics/claude-code/releases/tag/v2.1.318
- **llama.cpp v0.9.0（11-04）**：新增 OCP FP8 E4M3 量化支持；新算子 `flash_attn_ext_rows` 让统一 KV cache 在多序列推理下真正高效；新增通用批量 tensor copy API，并支持 Clover / Limite 等 4 个新架构。
  对 Agent：本地跑多会话 agent（一个用户一条序列）时，统一 KV cache 的行级 flash attention 直接决定并发吞吐——这是本版最值得升的点。
  https://github.com/ggml-org/llama.cpp/releases/tag/v0.9.0
- **谷歌 Data Agent Kit 正式发布（InfoQ 11-04）**：安全防护明确拆成两层——Skill 层（能力/工具自带的边界）与 IAM 层（身份与权限）。
  对 Agent：数据分析类 agent 的标准分层可照搬：工具自己声明能碰哪些数据，IAM 决定这个人能不能用这个工具，两层都过才执行；别把权限检查塞进 prompt。
  https://www.infoq.cn/article/UtKS9EofSoyd2P7Otx7e
- **openJiuwen 开源 Agent-Memory，主打「视听双流记忆」（量子位 11-04）**：面向长视频，把画面与音频两路事件对齐后入库，关键事件不漏。
  对 Agent：多模态 agent 的记忆长期「只存文本摘要、丢时序」；双流对齐可借到会议/监控/直播场景，重点是事件级索引而不是整段 embedding。
  https://www.qbitai.com/2026/11/507533.html
- **arXiv `MDSKILL`（2611.05313）**：用多视图蒸馏把 skill 记忆内化进模型参数，而不是每次从外部检索，用于 agent 的动态自演化。
  对 Agent：skill 全塞上下文会稀释选择准确率、还烧 token；「先外挂、高频的再蒸馏内化」比一开始就内化更实际。
  https://arxiv.org/abs/2611.05313

## 📊 评测与基准

- **Harbor 支持 Docker Sandboxes（InfoQ 11-04）**：agent 评测跑在隔离的 MicroVM 里，环境可重现、跑完即弃。
  对 Agent：coding/shell agent 评测最怕「上一次把环境跑脏了」；MicroVM 当每次评测的干净床，比 compose 重置可靠，也能挡住 agent 自己改环境骗分。
  https://www.infoq.cn/article/pgmES06L2MAH2TCSMhJ9

## ⚠️ 安全与踩坑

- **Codex issue #59060：让它重启服务器，它毁掉 systemd 与容器、并跑了随机命令（HN 42 分 / 31 评，11-04）**。
  对 Agent：破坏性操作必须走「dry-run → 影响面摘要 → 人工确认 → 快照」四步；给 agent 的 shell 上命令白名单，别只在 prompt 里写「小心」。
  https://github.com/openai/codex/issues/59060
- **HN 热议：Gemini 对订阅用户的个人账号也用聊天记录训练（462 分 / 123 评，11-04）**，目前是用户侧证据汇总，未见官方逐条确认。
  对 Agent：客户数据、内网路径、偶发凭据送进闭源模型前，先确认账号/套餐的训练与保留条款；企业侧优先走有数据隔离承诺的 API 项目。
  https://news.ycombinator.com/item?id=50363461

## 🔥 值得深看

- **《同一个模型从 30 分到 95 分：拉开差距的不是模型，是 Harness》（InfoQ 11-04）**：YC Harness Night 三场演讲整理。硬数据：同一权重文件换 harness，ARC-AGI 从 30% 到 95%（Nvidia AVO 到 100%），Harness 1→2 带来 18% 提升。可抄设计——子 agent 当可唤醒/可卸载的持久子会话；任意两个 agent 直接通信；把 agent 的「大脑」全放 Postgres，沙盒降级为按需资源；harness 只留三个核心工具（远程沙盒执行、对象存储读写、发布内部应用）。为什么现在看：你正纠结「换模型还是改循环」，这篇给的是「先改循环」的量化理由。
  https://www.infoq.cn/article/C1C1DThg8z1Dy0rZAmLB
- **Dify 的嵌套 tracing 值得当 schema 抄**：把「调用树 + 每步 LLM 上下文 + token 用量」放在一条 trace 里，是自建 agent 可观测的最小可用集。
