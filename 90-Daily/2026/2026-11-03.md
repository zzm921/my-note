## 🤖 大模型

- **美团 LongCat-2.5：官方定位「原生多模态 + Agentic 任务」，主打国芯国模**（官方博客 / 雷锋网 11-02）：标题口径是 "Native Multimodality for Agentic Tasks"，雷锋网称其在"国芯国模"上有新突破——即国产芯片上的训练/推理适配。
  对 Agent：多模态输入（截图、UI、文档）与工具调用放在同一个模型里完成，能省掉"截图→OCR→文本"这层胶水，GUI agent 的时延和错位都会小一截。注意：HF 镜像上 `meituan-longcat` 只有 LongCat-2.0 / Image / Video 系列，**未见 2.5 权重**，当前大概率只走 API，接入前先确认上下文长度与许可。
  https://longcat.ai/blog/longcat-2.5/
  https://www.leiphone.com/category/industrynews/mUPVr3RF0MHNmn3t.html
- **LeCun 新论文挑战 Scaling Law：1.09 亿参数胜过 720 亿**（InfoQ 11-02）：走的是世界模型 / JEPA 路线——让模型学习环境的可预测结构，而不是在 token 空间里堆参数拟合。
  对 Agent：这条线对应「预测与规划内核」，短期不替代负责工具调用的 LLM；如果你的 agent 要在环境里做多步推演（机器人、游戏、仿真），值得跟方法而不是跟"小模型打败大模型"的标题。
  https://www.infoq.cn/article/pWwkDpoFHIsfw9aCRkij

## 🧩 Agent 开发

- **Claude Code 悄悄在 Opus 5.5 的 system prompt 里加了两句「禁止复刻已有游戏」，Anthropic 已确认，结果 issue 被刷爆**（量子位 11-01，已核原文）：新增规则是"可做原创游戏、可做某类玩法的游戏、可用自己的素材；不得复刻已存在的特定游戏，改名或自称原创也不行"。副作用是纯原创项目写到一半被判定"疑似复刻"直接罢工。
  对 Agent：① prompt 级拒绝策略一定带来误杀，你的 agent 需要"拒绝率/误拒率"埋点，而不是只看通过率；② 这类策略是服务端随时改的，关键路径别押在未公开的 harness 行为上——上周的逆向能力话题，这周就变成了 harness 层的封堵。
  https://www.qbitai.com/2026/11/507038.html
- **crewAI 1.15.34（11-01）**：独立出 LiteLLM 模型目录（自建网关/自定义模型更省事）、`crewai run` 会记录 kickoff 前的停止位置（中断可续跑）、新增 `crewai skill search` 检索组织内 skill、`--inputs` 可把参数直传 Python flow。
  升级：`pip install -U crewai==1.15.34`；如果你用自建 LiteLLM 代理，这次是补齐模型清单最省事的一版。
  https://github.com/crewAIInc/crewAI/releases/tag/1.15.34
- **openai-python v3.42.1（11-01）**：唯一改动是修复 Responses WebSocket 的连接行为保持（#4221）。
  用 Responses API 的 WS 长连接跑流式工具调用的，这个补丁直接升级即可，改动面极小。
  https://github.com/openai/openai-python/releases/tag/v3.42.1
- **腾讯混元 Hy-Memory 2.0（★1922，Python）**：双系统认知记忆（System 1 快取 + System 2 慢整理），记忆分 8 层——原始对话、原子事实、摘要、schema、前瞻意图等，带冲突消解与跨域 schema 归纳；另有 Hy-Memory-30B-A3B 记忆写入模型（FP8 / GGUF 已开权重）、MemHub 桌面端与 CLI，编码场景还有专门的 CMB 长程记忆 benchmark。
  对 Agent：跨会话记忆别再自己造轮子，`pip install hy-memory==2.0.4` 先跑一版对照自研，重点看它"什么时候写、写哪一层、冲突怎么裁"这三条策略。
  https://github.com/Tencent-Hunyuan/Hy-Memory
- **《别再迷信 Agent 的自主性了》**（InfoQ 11-02）：核心论点是把确定性流程先做扎实，再谈放手。
  落到工程上：能写死的编排就别交给模型规划，自主性只留给真正开放的分支——这也是省 token 最直接的一刀。
  https://www.infoq.cn/article/UMvAAwoFByxvWLLVVJYY
- **Buildkite 的 CI 智能体思路：CI 挂了之后由 agent 判断"真回归还是 flaky"再把关**（InfoQ 11-02）。
  对 Agent：这是"可观测 + 门禁"的现成范式，可以照搬到自己的 nightly eval——让 agent 读失败日志、复跑单测、给出是否阻断的结论，人只看它升级上来的那部分。
  https://www.infoq.cn/article/WmlATgJudjwPKqHf4QgX

## 📊 评测与基准

- **arXiv 三篇正好补三个零件**：`TradeWar`（2610.41994）是 execution-grounded 的多智能体谈判基准，按执行结果而非对话打分；`ACCT`（2610.42096）做非对称跨 LLM 上下文迁移，解决"换模型不丢上下文"；`Flide`（2610.42128）用精确状态分叉加速决策推理，等价于"同一状态分叉多路试跑"。
  对 Agent：协商编排、上下文迁移、多路试跑——这三块恰好是多数自研 agent 最缺测试手段的地方，可以直接拿来做回归。
  https://arxiv.org/abs/2610.41994
