# 每日一练 · 进度与规则

> 跟着**正在学的内容**出题，不按固定题库、不发散。
> 每天 3 题（概念 / 原理 / 实操）+ 1 条知识推荐，题源就是库内对应章节笔记的内容。
> 推送时间：每日 09:00；同时追加到本目录对应章节文件，只加不改。

## 出题风格（用户偏好，2026-09-19 起）

- **用户用语音作答** → 题目要能「讲出来」：少出计算题、不出纯算术题（他明确说计算题帮助不大）
- 每题构成改为：**① 概念解释**（是什么/为什么/区别在哪）+ **② 机制理解**（为什么这样设计、改掉会怎样）+ **③ 应用判断**（在工程/Agent 场景里怎么用、坑在哪）
- 涉及公式时的考法：**说清由哪些因素决定、量级怎么估、计算步骤是什么**，而不是报出具体数字
- 判定按「要点覆盖」：关键点讲到即算对，不因为没有精确数字判错
- **2026-09-20 起：一问一答** —— 每天只发 1 道题（当天复习题优先、复习题答完接新题），答完再发下一道；全部答完做日终复盘

## 学习目标定位

- 目标岗位：**AI Agent 工程师**；学机器学习是**完善技术储备**（理解原理、能判断、能用在 Agent 工程里），不是转做算法研究
- 因此知识推荐尽量关联 Agent 场景（如表示学习/embedding 与 RAG、训练与推理成本、评测方法），但**只作为延伸阅读，不出未学章节的题**

## 规则

1. **只出「已经学过」的内容**：`00-进度.md` 里状态为「进行中 / 已完成」的章节才出题；标「待开始」的章节**绝不出题**（用户还没学，提前考没意义）。
2. **一章出完不着急进新章节** → 进入「**巩固轮**」：从已学章节里挑没考过的知识点混合出题（可跨章节，但必须都在已学范围内）。新章节只有在用户说「开始学 X」时才切成「进行中」。
3. **题源**：以 `10-AI/ml/<章节>.md` 该章的 `##` 小节为主线，按小节顺序逐日推进。
2. 每天 3 题：1 概念（说清是什么/为什么）+ 1 原理或计算（能推能算）+ 1 实操或直觉（能画能写代码）。
3. 附「知识推荐」：1 条补强（本章薄弱点或易错点）+ 1 条延伸（关联章节或可跑的开源实现）。
4. 用户报进度（「学到 X 了」）时，切换章节并在本表登记。
