### Q1 · 概念 ★｜决策树是「怎么长出来」的？每次分裂在优化什么？为什么说它天然可解释？

**考点**：递归划分的基本机制；「纯度」作为分裂目标；可解释性的来源。

**答案要点**

1. **长树的过程就是递归二分**：从根节点（全部样本）开始，每个节点挑一个特征和一个切分点，把样本分成两组；对子节点重复，直到满足停止条件，叶节点给出预测（分类=多数类，回归=均值）。
2. **每次分裂在优化「纯度」**：希望分完以后每个子集里的样本**更同质**——分类用熵/基尼指数衡量，回归用方差/MSE 衡量；分裂点选「分完之后加权不纯度下降最多」的那个。
3. **它是贪心算法**：每一步只挑当前最优切分，不回溯、不保证全局最优——这是它快的原因，也是它容易过拟合的原因。
4. **可解释性来自结构本身**：每个样本的预测对应一条「根 → 叶」的路径，每条边都是「某特征 是否 > 阈值」的判定，所以能直接讲给业务方听（这也是它在风控、医疗、审核规则里长盛不衰的原因）。
5. **代价**：对训练数据极度敏感——数据稍微一变树结构就可能大变；单棵树方差大、不稳定。

**追问**：为什么决策树不需要做特征缩放（标准化）？→ 分裂只依赖**特征取值的相对顺序**（阈值比较），单调变换（缩放、取对数）不改变可用的切分点，所以缩放对结果几乎没影响。

**易错点**：以为决策树会「同时优化全部切分」（其实是贪心逐节点）；把「可解释」误解为「一定准」。

### Q2 · 概念对比 ★★｜熵、信息增益、基尼指数分别在衡量什么？用基尼替代熵有什么工程好处？

**考点**：不纯度度量的含义与取舍。

**答案要点**

1. **熵**衡量一个集合的「混乱程度」：类别分布越均匀、熵越大；全同类时为 0。它是信息量的期望，单位是比特。
2. **信息增益 = 分裂前的熵 − 分裂后各子集熵的加权平均**，也就是「这次分裂帮我们消除了多少不确定性」——ID3 用它选题，但**它偏好取值多的特征**（把样本切得很碎也能降低熵），所以有偏差。
3. **基尼指数**是「随机抽两个样本，类别不一致的概率」，形式上比熵少一个对数；**CART 用它**做分裂准则。
4. **工程好处**：基尼只涉及乘法与减法、**没有对数运算**，在大数据/流式计算里更快、更好并行；实践中它和熵选出的树**效果通常很接近**，所以现代实现默认基尼。
5. **为什么还要知道熵**：交叉熵、KL 散度、互信息这些更通用的概念都由它衍生；理解熵才能理解「信息增益偏好多值特征」这类偏差，以及 C4.5 用**增益率**修正它的做法。

**追问**：如果某个特征取值极多（比如用户 ID），信息增益会怎样？→ 会很高甚至接近「完全分开」，但那是**记忆而非泛化**，所以要么用增益率惩罚，要么干脆不用高基数特征。

**易错点**：把信息增益当成「越大越泛化好」；把基尼和熵当两套完全不同的东西（本质都是不纯度度量）。

### Q3 · 机制理解 ★★｜决策树为什么特别容易过拟合？预剪枝和后剪枝各在防什么、代价是什么？

**考点**：过拟合的成因；两种剪枝的取舍。

**答案要点**

1. **过拟合的根因**：树可以一直分裂到每个叶节点只剩一个样本（纯度 100%），把噪声也当成规律记下来；深度越大、叶子越多，模型越接近「查表」。
2. **预剪枝**（边建边停）：设最大深度、叶节点最小样本数、最小不纯度下降阈值。优点：快、省；缺点：**可能欠拟合**——当前分裂看起来没收益，但再往下分两步才有收益，贪心会过早停手。
3. **后剪枝**（先长满再回剪）：自底向上评估每个子树，若「剪掉后验证集误差不升」就剪。优点：**效果通常更好**；缺点：训练代价大、需要额外的验证数据。
4. **工程上的现实选择**：多数库（sklearn 等）默认靠**超参控制**（max_depth / min_samples_leaf / ccp_alpha 代价复杂度剪枝）来近似预剪枝 + 后剪枝的组合，比手工剪枝更省事。
5. **和「少计算」无关的核心结论**：单棵树的方差大，靠**限制复杂度**只能缓解；真正压方差靠的是**集成**（见 Q4）。

**追问**：把 max_depth 调小一定更不容易过拟合吗？→ 方向对，但调过头就欠拟合；正确做法是用验证集/交叉验证找拐点，而不是拍一个数。

**易错点**：把「训练集准确率高」当过拟合的唯一判据（要看训练-验证差距）；以为剪枝能解决数据本身有噪声的问题。

### Q4 · 机制理解 ★★｜随机森林的「随机」体现在哪两处？为什么这两处随机能降低方差？

**考点**：bagging 与特征采样的作用；方差-偏差视角。

**答案要点**

1. **第一处随机：样本随机**（bagging）——每棵树用**有放回抽样**得到一份和原数据集等大的训练集，约 1/3 样本没被抽到（OOB，可当免费验证集）。
2. **第二处随机：特征随机**——每次分裂只在**随机抽取的一部分特征**里挑最优切分，而不是全部特征。
3. **为什么能降方差**：单棵树对数据扰动极敏感（高方差）；对很多棵**近似独立**的树取平均，方差按相关性折扣下降——树之间越不相关，平均后越稳。特征采样正是用来**降低树之间的相关性**（否则强特征会让所有树长得很像，平均就没用了）。
4. **偏差基本不变**：每棵树都是在新样本上尽力拟合，平均不会显著增加偏差；所以随机森林是「几乎免费」地把方差打下来。
5. **代价**：模型变大（几十到几百棵）、推理变慢、失去单棵树的直接可解释性（要靠特征重要性/OOB 等近似手段）。

**追问**：为什么随机森林「加深树」通常不严重有害？→ 因为单棵树的过拟合会被集成平均抵消；这也是随机森林常把树长满、不剪枝的原因。

**易错点**：把随机森林当成「更准的决策树」而不是「方差的平均」；忘了特征采样才是它区别于普通 bagging 的关键。

### Q5 · 应用判断 ★★｜用随机森林做特征重要性有哪些坑？在 Agent 工程里你会怎么用这个信号？

**考点**：不纯度重要性的偏差与替代方案；特征重要性的工程用法。

**答案要点**

1. **默认的「不纯度重要性」有偏差**：它偏爱**高基数/连续**特征（这类特征能提供更多切分点、更容易降低不纯度），也可能把相关性强的特征之间互相分摊/稀释——所以不能直接当因果结论。
2. **更可信的替代**：**置换重要性**（打乱某列后看验证指标跌多少，在验证集上算）；或直接用**permutation / drop-column** 做对照。代价是计算量更大。
3. **相关性特征要成组看**：两个高度相关的特征，重要性会被分掉一半，看起来都「不重要」——应按业务分组做**组内置换**。
4. **Agent 工程里的用法**：把随机森林当**「小模型判定器 + 归因工具」**——例如工具调用的路由打分、检索结果是否相关的初筛；用重要性找「哪些上下文特征真的影响成功率」，然后反过来指导 **prompt/上下文精简**（砍掉贡献近零的特征与字段，省 token、降延迟）。
5. **边界**：重要性只说明「模型在用哪些信号」，不等于业务因果；上线前仍要用**独立测试集/线上 A-B** 验证，别拿重要性当结论发出去。

**追问**：如果某个特征重要性很高，但去掉它模型效果不变，怎么解释？→ 大概率存在**高度相关的替身特征**（信息可由其他列还原），或者是过拟合信号；应做 drop-column 实验确认。

**易错点**：拿不纯度重要性直接写进结论；在有强相关特征时不分组解读。

### Q6 · 概念 ★★｜连续特征（如体重 5.0~8.0）为什么不能像离散特征那样「一个取值一个分支」？阈值分裂怎么做、代价在哪？

**考点**：连续特征的切分方式；候选阈值取相邻中点；与类别特征成支的区别；复杂度与工程近似。

**答案要点**

1. **根因是取值几乎不重复**：连续特征（体重、时长、金额）每个样本一个值，按取值分支就变成「一个样本一支」——分支爆炸、等于查表，毫无泛化。所以对连续特征只能改问「是否大于某个阈值」这类二分问题。
2. **阈值分裂的做法**：把该特征的值**排序**，只取**相邻两个取值的中点**当候选阈值 t（n 个样本最多 n−1 个候选点，不需要遍历所有实数）；对每个候选按 `x ≤ t` / `x > t` 分成两支，算「分裂后不纯度下降」（分类看信息增益/基尼下降，回归看方差降低），选最好的那个 t。
3. **和类别特征的差别**：类别特征按取值成支（取值有限、天然就是几支）；连续特征是用阈值把数轴切成区间，而且**同一个特征可以在树的不同深度反复使用、每次用不同阈值**——所以整棵树相当于把连续轴切成若干区间，用阶梯状的分段常数去逼近一个函数。
4. **代价一（计算）**：候选点数量随样本数线性增长，特征多、样本大时每次找分裂点都很贵；工程上改用**近似分桶 / 直方图**（XGBoost 的近似分裂、LightGBM 的直方图）把候选点压到常数级——这是拿一点精度换速度，不是免费优化。
5. **代价二（稳定性）**：阈值只要挪一点点，边界附近的样本就换到另一支，树结构可能整体变样——这正是「单棵树方差大、要靠集成来压」的一个具体来源。

**追问**：阈值分裂既然能把连续轴切成很多区间，为什么还要限制深度或叶子最小样本数？→ 切得太细≈给每个样本一个格子，把噪声也装进去了；所以要靠 max_depth / min_samples_leaf / 剪枝约束「最多能切多细」。

**易错点**：以为要先手工分箱（离散化）才能进树（树自己会找阈值）；以为要遍历所有实数找阈值（只需相邻中点）；把「阈值二分」和「按类别成支」混为一谈。

### Q7 · 机制理解 ★★｜回归树为什么把分裂标准从「信息增益」换成「方差降低」、叶子为什么输出均值而不是多数类？

**考点**：回归树的不纯度度量（方差 / MSE）与叶预测值；与分类树的对应关系及代价。

**答案要点**

1. **框架不变，只换「纯度的尺子」**：一样是递归 + 贪心 + 阈值分裂；分类看「标签分布是否同质」（熵 / 基尼），回归的标签是**数字**，「同质」自然就是**数值分散程度小** → 改用方差（MSE）。
2. **形式完全对应**：`ΔVar = Var(节点) − Σⱼ (nⱼ/n)·Var(Dⱼ)`，与信息增益一样是「分裂前不纯度 − 分裂后加权不纯度」，只是不纯度定义换成方差——记法不变：选「降得最多」的那个特征/阈值。
3. **叶子取均值的原因**：子集内让平方误差 `Σ(yᵢ−c)²` 最小的常数 c 就是**均值 ȳ**——均值不是拍脑袋定的，而是「最小化平方误差」的自然解；分类树对应的自然选择则是「多数类」。
4. **不能沿用分类那一套的原因**：数值标签没有天然的「类」可数，硬分箱会把连续的数值信息压成几个档（还多出箱边界这种人为超参）；而「多数类」对回归根本没有定义。**分裂准则和叶子输出必须与预测目标一致**，否则优化目标和最终指标对不上。
5. **代价 / 注意点**：MSE 对离群值敏感（平方把大残差放大），叶均值会被极端点拉偏——评估时要配 MAE / R² 和残差图一起看；确实需要稳健时，可以换用绝对误差（MAE）型的分裂准则，或先对目标做变换。
6. **和 Agent 工程的关系**：回归树常用来预测「一个分数」（成本、时延、打分），此时叶均值＝该区间样本的平均表现，ΔVar 大＝切出的区间内表现更一致；解读时务必连着**叶子样本数**看，样本太少的叶子均值本身噪声大。

**追问**：如果先给回归标签分箱、再用分类树做预测，损失了什么？→ 丢掉数值大小信息（只留了顺序），箱边界变成人为超参，叶子只能输出箱的代表值——一般不如直接建回归树。

**易错点**：拿信息增益 / 多数类去做回归树；以为回归树不用剪枝（一样要，原理相同）；把「ΔVar 最大」当成「最终误差一定最小」的保证（它只是贪心分裂准则）。

### Q8 · 概念 + 机制 ★★｜信息增益为什么会「偏爱」取值很多的特征（比如用户 ID）？增益率和 CART 的基尼指数怎么修正这一点？为什么现代实现默认用 CART？

**考点**：信息增益的偏向性（高基数特征）；ID3 / C4.5 / CART 三种算法的差别；二叉切分与基尼指数的工程理由。

**答案要点**

1. **偏爱从哪来**：信息增益 = 分裂前熵 − 分裂后**加权**熵。取值多的特征可以把样本切成很多小块，块越小越纯（极端情况：每个取值一块、每块只剩一个样本 → 每块熵为 0，增益看起来最大）。这是「**用分裂数量换纯度**」的取巧 —— 它只是记住了样本，没有泛化。
2. **最典型的坑是 ID 类特征**：用户 ID / 订单号这种「每行都不同」的高基数特征，增益几乎总是最高；按增益自动选特征，树会拿它做根节点 → 训练集漂亮、验证集崩。**特征基数本身就是信息量之外的干扰项。**
3. **C4.5 的修正：增益率** = 信息增益 ÷ 该特征自身的分裂熵（intrinsic value），相当于给「切得越碎」的特征加罚。实践中先按增益粗筛、再用增益率选，否则会矫枉过正到只挑几乎不分叉的特征。
4. **CART 的修正：只做二叉 + 换尺子**：每次分裂只问「某特征 是否 > 阈值」（二分成两块），不纯度改用**基尼指数** `Gini = 1 − Σpₖ²`（随机抽两个样本、标签不同的概率）。二叉切分天然限制了「切碎换纯度」的空间，而且不用算 log、更快。
5. **为什么现代默认 CART**：分类与回归共用同一套框架（回归把基尼换成方差/MSE）；不用算 log、数值稳；产出固定二叉树便于剪枝（`ccp_alpha`）；sklearn 用的就是 CART 系的实现。
6. **工程用法（延伸）**：高基数类别特征别直接喂树 —— 先聚合/分箱成低基数、有概括力的特征（把「用户 ID」换成「用户等级」「近 30 天活跃档」），或改用目标编码类做法；判断标准始终是**训练-验证得分差距**，不是训练集纯度。

**追问**：基尼指数和熵一定给出同一棵树吗？→ 不保证。两者只是「不纯度」的两把尺子，候选分裂的排序在多数数据上接近但不总相同；实际差异通常远小于「换特征工程」带来的差异。

**易错点**：以为信息增益越高越该选（忽略基数偏向）；把基尼和熵当成一回事（数值范围与计算代价不同）；把 ID 类特征当「很有信息的强特征」。

### Q9 · 机制理解 ★★｜决策树为什么不需要特征缩放，而线性回归 / 梯度下降必须先做？什么时候「不用缩放」这件事又不成立了？

**考点**：分裂只依赖单个特征的取值顺序；线性模型的尺度敏感性（共享学习率与等高线形状）；「不需要缩放」的边界条件。

**答案要点**

1. **分裂的本质是阈值比较**：每个节点在**某一个**特征上问「xⱼ > t ?」。树只关心该特征内部的**相对大小（排序）**，不关心绝对值：把面积从「平方米」换成「平方厘米」，阈值跟着放大 10000 倍，**切出来的分组完全一样、树结构一模一样**（单调变换不改变树）。
2. **树从不跨特征比较量纲**：一次分裂只看一个特征，不需要把「房间数 1~5」和「面积 50~300」放进同一个算式相加相乘；而线性模型要算 `w·x`，不同量纲的特征直接进同一个加权和，权重只能去迁就各自的尺度。
3. **线性模型 / 梯度下降为什么敏感**：更新量 = α × 梯度，**同一个 α 对所有参数共用**；尺度差几个数量级时代价函数等高线被拉成细长椭圆，梯度方向几乎垂直于谷底 → 只能小步慢走、来回震荡，收敛极慢甚至发散（第 3 章）。树没有「全局学习率」这一步，自然没有这个问题。
4. **所以预处理的重心不同**：线性模型 / 逻辑回归靠**缩放 + 特征工程**改善优化；树靠**控制复杂度（深度 / 叶子样本数 / 剪枝）+ 有含义的分箱与特征组合**改善泛化 —— 对树来说缩放基本是空操作。
5. **什么时候「不用缩放」又不成立**：① 模型/流水线里带**惩罚项**时（L2 惩罚 `λ·Σwⱼ²` 与尺度绑定，做正则化的线性模型必须先缩放）；② 需要**跨特征比较大小**的信号时（不同模型的重要性排序、距离/相似度类方法 —— 后者属于后面章节，不作考点）；③ 同一条预处理管线喂多个模型时，统一缩放最省事。
6. **Agent 场景（延伸）**：树类模型当「判定器 / 路由」时，工程重心不是归一化，而是**特征是否有可判断的含义**（上下文长度档、工具调用次数档、超时次数…）与**深度/叶子样本数**；顺序搞反（先去调缩放、再调结构）会白花时间。

**追问**：给树喂一个「保持顺序不变」的变换（正值域上取 log、开平方），树会变吗？→ 不会。单调变换不改变排序，候选阈值（相邻取值中点）只是换了坐标，而分裂收益（熵/基尼/方差）只依赖分组结果，所以完全一样。

**易错点**：以为「决策树很聪明所以自动免疫一切量纲问题」（它只是不需要缩放，仍受特征基数、特征含义影响）；把「不用缩放」套到所有模型/流水线上；反过来以为树也需要归一化而白做预处理。
