### Q1 · 概念 ★｜决策树是「怎么长出来」的？每次分裂在优化什么？为什么说它天然可解释？

**考点**：递归划分的基本机制；「纯度」作为分裂目标；可解释性的来源。

**答案要点**

1. **长树的过程就是递归二分**：从根节点（全部样本）开始，每个节点挑一个特征和一个切分点，把样本分成两组；对子节点重复，直到满足停止条件，叶节点给出预测（分类=多数类，回归=均值）。
2. **每次分裂在优化「纯度」**：希望分完以后每个子集里的样本**更同质**——分类用熵/基尼指数衡量，回归用方差/MSE 衡量；分裂点选「分完之后加权不纯度下降最多」的那个。
3. **它是贪心算法**：每一步只挑当前最优切分，不回溯、不保证全局最优——这是它快的原因，也是它容易过拟合的原因。
4. **可解释性来自结构本身**：每个样本的预测对应一条「根 → 叶」的路径，每条边都是「某特征 是否 > 阈值」的判定，所以能直接讲给业务方听（这也是它在风控、医疗、审核规则里长盛不衰的原因）。
5. **代价**：对训练数据极度敏感——数据稍微一变树结构就可能大变；单棵树方差大、不稳定。

**追问**：为什么决策树不需要做特征缩放（标准化）？→ 分裂只依赖**特征取值的相对顺序**（阈值比较），单调变换（缩放、取对数）不改变可用的切分点，所以缩放对结果几乎没影响。

**易错点**：以为决策树会「同时优化全部切分」（其实是贪心逐节点）；把「可解释」误解为「一定准」。

### Q2 · 概念对比 ★★｜熵、信息增益、基尼指数分别在衡量什么？用基尼替代熵有什么工程好处？

**考点**：不纯度度量的含义与取舍。

**答案要点**

1. **熵**衡量一个集合的「混乱程度」：类别分布越均匀、熵越大；全同类时为 0。它是信息量的期望，单位是比特。
2. **信息增益 = 分裂前的熵 − 分裂后各子集熵的加权平均**，也就是「这次分裂帮我们消除了多少不确定性」——ID3 用它选题，但**它偏好取值多的特征**（把样本切得很碎也能降低熵），所以有偏差。
3. **基尼指数**是「随机抽两个样本，类别不一致的概率」，形式上比熵少一个对数；**CART 用它**做分裂准则。
4. **工程好处**：基尼只涉及乘法与减法、**没有对数运算**，在大数据/流式计算里更快、更好并行；实践中它和熵选出的树**效果通常很接近**，所以现代实现默认基尼。
5. **为什么还要知道熵**：交叉熵、KL 散度、互信息这些更通用的概念都由它衍生；理解熵才能理解「信息增益偏好多值特征」这类偏差，以及 C4.5 用**增益率**修正它的做法。

**追问**：如果某个特征取值极多（比如用户 ID），信息增益会怎样？→ 会很高甚至接近「完全分开」，但那是**记忆而非泛化**，所以要么用增益率惩罚，要么干脆不用高基数特征。

**易错点**：把信息增益当成「越大越泛化好」；把基尼和熵当两套完全不同的东西（本质都是不纯度度量）。

### Q3 · 机制理解 ★★｜决策树为什么特别容易过拟合？预剪枝和后剪枝各在防什么、代价是什么？

**考点**：过拟合的成因；两种剪枝的取舍。

**答案要点**

1. **过拟合的根因**：树可以一直分裂到每个叶节点只剩一个样本（纯度 100%），把噪声也当成规律记下来；深度越大、叶子越多，模型越接近「查表」。
2. **预剪枝**（边建边停）：设最大深度、叶节点最小样本数、最小不纯度下降阈值。优点：快、省；缺点：**可能欠拟合**——当前分裂看起来没收益，但再往下分两步才有收益，贪心会过早停手。
3. **后剪枝**（先长满再回剪）：自底向上评估每个子树，若「剪掉后验证集误差不升」就剪。优点：**效果通常更好**；缺点：训练代价大、需要额外的验证数据。
4. **工程上的现实选择**：多数库（sklearn 等）默认靠**超参控制**（max_depth / min_samples_leaf / ccp_alpha 代价复杂度剪枝）来近似预剪枝 + 后剪枝的组合，比手工剪枝更省事。
5. **和「少计算」无关的核心结论**：单棵树的方差大，靠**限制复杂度**只能缓解；真正压方差靠的是**集成**（见 Q4）。

**追问**：把 max_depth 调小一定更不容易过拟合吗？→ 方向对，但调过头就欠拟合；正确做法是用验证集/交叉验证找拐点，而不是拍一个数。

**易错点**：把「训练集准确率高」当过拟合的唯一判据（要看训练-验证差距）；以为剪枝能解决数据本身有噪声的问题。

### Q4 · 机制理解 ★★｜随机森林的「随机」体现在哪两处？为什么这两处随机能降低方差？

**考点**：bagging 与特征采样的作用；方差-偏差视角。

**答案要点**

1. **第一处随机：样本随机**（bagging）——每棵树用**有放回抽样**得到一份和原数据集等大的训练集，约 1/3 样本没被抽到（OOB，可当免费验证集）。
2. **第二处随机：特征随机**——每次分裂只在**随机抽取的一部分特征**里挑最优切分，而不是全部特征。
3. **为什么能降方差**：单棵树对数据扰动极敏感（高方差）；对很多棵**近似独立**的树取平均，方差按相关性折扣下降——树之间越不相关，平均后越稳。特征采样正是用来**降低树之间的相关性**（否则强特征会让所有树长得很像，平均就没用了）。
4. **偏差基本不变**：每棵树都是在新样本上尽力拟合，平均不会显著增加偏差；所以随机森林是「几乎免费」地把方差打下来。
5. **代价**：模型变大（几十到几百棵）、推理变慢、失去单棵树的直接可解释性（要靠特征重要性/OOB 等近似手段）。

**追问**：为什么随机森林「加深树」通常不严重有害？→ 因为单棵树的过拟合会被集成平均抵消；这也是随机森林常把树长满、不剪枝的原因。

**易错点**：把随机森林当成「更准的决策树」而不是「方差的平均」；忘了特征采样才是它区别于普通 bagging 的关键。

### Q5 · 应用判断 ★★｜用随机森林做特征重要性有哪些坑？在 Agent 工程里你会怎么用这个信号？

**考点**：不纯度重要性的偏差与替代方案；特征重要性的工程用法。

**答案要点**

1. **默认的「不纯度重要性」有偏差**：它偏爱**高基数/连续**特征（这类特征能提供更多切分点、更容易降低不纯度），也可能把相关性强的特征之间互相分摊/稀释——所以不能直接当因果结论。
2. **更可信的替代**：**置换重要性**（打乱某列后看验证指标跌多少，在验证集上算）；或直接用**permutation / drop-column** 做对照。代价是计算量更大。
3. **相关性特征要成组看**：两个高度相关的特征，重要性会被分掉一半，看起来都「不重要」——应按业务分组做**组内置换**。
4. **Agent 工程里的用法**：把随机森林当**「小模型判定器 + 归因工具」**——例如工具调用的路由打分、检索结果是否相关的初筛；用重要性找「哪些上下文特征真的影响成功率」，然后反过来指导 **prompt/上下文精简**（砍掉贡献近零的特征与字段，省 token、降延迟）。
5. **边界**：重要性只说明「模型在用哪些信号」，不等于业务因果；上线前仍要用**独立测试集/线上 A-B** 验证，别拿重要性当结论发出去。

**追问**：如果某个特征重要性很高，但去掉它模型效果不变，怎么解释？→ 大概率存在**高度相关的替身特征**（信息可由其他列还原），或者是过拟合信号；应做 drop-column 实验确认。

**易错点**：拿不纯度重要性直接写进结论；在有强相关特征时不分组解读。
